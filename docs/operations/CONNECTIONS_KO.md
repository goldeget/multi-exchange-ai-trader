# 연결 등록과 실제 확인

`GET /api/v1/connections/status`는 서버가 가진 설정과 로컬 저장소 상태를 보여 줍니다. 이 조회는 계좌나 모델 제공자에게 요청하지 않습니다. `REGISTERED_UNVERIFIED`는 설정 등록이며, 인증 성공·권한 확인·잔고 확인이 아닙니다. `verified_at`은 아직 `null`입니다.

## Anthropic

현재 구현은 키 존재 여부와 모델 이름의 형식 확인까지입니다. Anthropic 생성 클라이언트와 실제 모델 호출은 아직 구현하지 않았습니다. 키를 등록해도 `mode=OFFLINE_TEST`, `external_calls=false`가 유지됩니다. AI 설정 API의 사용 가능한 모드와 기존 예산 설정은 바뀌지 않습니다. 제공자 실제 잔고는 조회하지 않으며, 월 한도나 로컬 기록을 실제 잔고로 해석하지 않습니다.

서버 프로세스 환경 변수 `ANTHROPIC_API_KEY`, `ANTHROPIC_MODEL`을 사용합니다. 파일을 쓰려면 `ANTHROPIC_ENV_FILE`에 개인 자격 증명 파일의 경로를 명시합니다. 기본 `.env` 자동 검색은 없습니다. `off`, `none`, `0` 또는 빈 값은 파일 읽기를 끕니다. 파일에서 읽은 값은 프로세스 환경에 내보내지 않으며, 비어 있지 않은 프로세스 환경 값이 파일보다 우선합니다. 앱 시작 때 한 번 읽으므로 변경 후 서버를 다시 시작해야 합니다.

파일은 UTF-8의 `NAME=value` 한 줄 형식입니다. 빈 줄, `#`로 시작하는 주석, `export NAME=value`, 값 전체를 감싼 작은따옴표·큰따옴표를 허용합니다. 보간·명령 실행·줄 끝 주석은 지원하지 않습니다. 이 로더는 두 Anthropic 항목만 사용하므로 별도 Bybit 항목과 파일을 공유할 수 있습니다. 중복 Anthropic 항목, 잘못된 형식, 읽을 수 없는 명시 파일은 오류입니다. 파일은 일반 파일이어야 하며 심볼릭 링크·디렉터리 연결은 허용하지 않습니다. 최대 16 KiB, 256줄입니다.

공유할 수 있는 빈 예시:

```dotenv
ANTHROPIC_API_KEY=
ANTHROPIC_MODEL=
```

실제 키는 저장소 밖 개인 폴더에 직접 보관합니다. Windows에서는 사용자 프로필 아래 `.config\trader\credentials.env`, Linux에서는 `~/.config/trader/credentials.env` 같은 경로를 사용할 수 있습니다. 빈 예시 파일은 자격 증명 등록이나 연결 확인의 증거가 아닙니다. 실제 값을 채팅·화면·로그·Git에 복사하지 않습니다. 사용할 PC에서 소유자만 읽을 수 있도록 파일 권한을 설정한 뒤, 그 PC의 서버에 실제 파일 경로를 지정합니다. Linux의 배포 예시는 `LINUX_DEPLOYMENT_KO.md`를 따릅니다.

모델 이름은 제공자의 정확한 모델 ID를 직접 지정해야 합니다. `5.5 하이쿠`라는 표현으로 ID를 추측하거나 자동 치환하지 않습니다. 공개 응답의 `model_id`는 제한된 `claude-...` 형식을 통과하고 입력된 Anthropic 키를 포함하지 않는 문자열만 포함합니다. 환경 값으로 덮어쓴 파일 키도 검사합니다. 형식 통과는 실제 모델 존재나 사용 가능 여부의 검증이 아닙니다.

| 상태 | 의미 |
| --- | --- |
| `NOT_CONFIGURED` | 사용할 키가 비어 있음 |
| `REGISTERED_UNVERIFIED` | 키가 등록됨. 모델 지정은 선택 사항이며 접근 검증은 아직 없음 |
| `INVALID_CONFIGURATION` | 설정 형식 또는 명시 파일 읽기 오류. 원문과 경로는 응답하지 않음 |
| `STORAGE_UNAVAILABLE` | 로컬 AI 예산 저장소를 사용할 수 없음. 키 등록 여부와 별개의 차단 상태 |

`registered`는 키 존재 정보입니다. 예를 들어 키가 있고 모델 형식이 틀리면 등록 여부는 참이지만 상태는 `INVALID_CONFIGURATION`이며 `model_id`는 공개하지 않습니다. 오류가 있어도 유료 호출이나 자동 거래를 시작하지 않습니다.

## Bybit

실계좌 읽기와 DEMO 주문은 분리된 경로입니다. `BYBIT_DEMO=true`는 실계좌 읽기 클라이언트의 메인넷 주소를 데모 주소로 바꾸지 않습니다. DEMO 전용 키가 등록되면 별도의 승인 경로에서 실제 데모 주문을 보낼 수 있으므로, 기본 배포에서는 끕니다. 자세한 효과와 한계는 [Bybit 계좌 조회 문서](../account/BYBIT_READONLY.md)를 확인합니다. 서버 생존 확인이나 이 연결 상태 조회를 위해 DEMO 승인을 실행하지 않습니다.
