## Ownership and event proof

Official [order stream](https://bybit-exchange.github.io/docs/v5/websocket/private/order) fields include orderId/orderLinkId, createType/stopOrderType, positionIdx, trigger fields, quantities, reduceOnly, closeOnTrigger and timestamps. There is no documented generic linear parent-entry ID in that schema. Classification, matching prices, timing, same symbol or `positionIdx=0` are insufficient parent proof. The [open-order schema](https://bybit-exchange.github.io/docs/v5/order/open-order) likewise does not supply a generic entry-parent relationship; closed realtime history is bounded and may clear after server restarts.

Pinned [HTTP order model L879–921](https://github.com/nautechsystems/nautilus_trader/blob/27a8e54e7ac3c57d6cbf8891f0283dfbaee97317/crates/adapters/bybit/src/http/models.rs#L879-L921) has TP/SL values and classification but no parent field. [WS normalization L803–856](https://github.com/nautechsystems/nautilus_trader/blob/27a8e54e7ac3c57d6cbf8891f0283dfbaee97317/crates/adapters/bybit/src/websocket/parse.rs#L803-L856) preserves child venue ID, optional nonempty client ID, conditional trigger/source and reduce-only. [Fill normalization L918–938](https://github.com/nautechsystems/nautilus_trader/blob/27a8e54e7ac3c57d6cbf8891f0283dfbaee97317/crates/adapters/bybit/src/websocket/parse.rs#L918-L938) allows an empty client ID and no venue position ID. It does not add parent lineage. Python [L1698–1710](https://github.com/nautechsystems/nautilus_trader/blob/27a8e54e7ac3c57d6cbf8891f0283dfbaee97317/nautilus_trader/adapters/bybit/execution.py#L1698-L1710) copies linked IDs from its existing cache; those are not independent exchange evidence.

Consequently, attached children without authoritative lineage remain unowned/ambiguous; do not manufacture `ec_...` IDs, assign the parent client ID to a child, or adopt a manual order. A distinct position-level protection model would be a deliberate alternative design, requiring exclusive account/symbol ownership and its own qualification; it is not a shortcut to satisfying the current child-order model.

For independently submitted protective orders, ownership can instead originate from exact precommitted client ID + immutable command + strategy/account/environment binding, then join authenticated venue orderId and execution IDs. Keep external orders visible as blockers without claiming them. Bybit [execution stream](https://bybit-exchange.github.io/docs/v5/websocket/private/execution) exposes execId/orderId/orderLinkId, quantity, price, fee and time; its symbol-scoped sequence associates execution/position updates, not entry-child lineage. [Execution history](https://bybit-exchange.github.io/docs/v5/order/execution) requires explicit bounded windows and cursor traversal; one terminal order status, one page, or an empty result is not complete execution history.

## Restart and NETTING

## Current application mismatch

Paths below are relative to `src/multi_exchange_trader/execution/` and correspond to the hashes above.

- `bybit_native.py:89–115` admits only ENTRY/EXIT MARKET/LIMIT. `command_params:122–130` encodes attached protection. There is no STOP/TAKE_PROFIT request/factory/repair dispatch. `register_owned:181–190` restores an application map only; `cached_owned_order:244–261` deliberately requires actual active native cache state for cancellation.
- `runtime.py:166–173` restores ENTRY/EXIT mappings; `_request:387–408` supports those roles only. `consume_readback:944–955` accepts protection only for already-owned STOP/TAKE_PROFIT IDs, yet this runtime never creates/registers such commands. Attached children therefore cannot satisfy this path automatically.
- `protection.py:402–425,465–549` requires exact immutable owned IDs, matching policy/generation, active status, source/price, current exclusive position, and exact remaining quantity. These safety checks are appropriate. Do not weaken them to match attached children by price or symbol.
- `runtime.py:854–881` has a scoped reduce-only exit gate and rejects unowned open orders. That is a useful prerequisite, not a complete provenance proof: equal net quantity alone cannot prove absence of external activity. `runtime.py:958–962` correctly keeps authentication unresolved. `_require_qualification:194–195` still blocks effects.
- `native_events.py:191–206` and `runtime.py:818–831` currently lack explicit actual-versus-inferred execution provenance. Exact native class identity is insufficient once live reconciliation is attached. This gap should be closed before enabling native lifecycle callbacks.
- `docs/implementation/NATIVE_QUALIFICATION.md` describes isolated native/offline qualifications. `BYBIT_NATIVE_BRIDGE_KO.md:3,54–56,66–72` explicitly does not qualify actual DEMO, child ownership, or dynamic trading-stop. No stronger claim is supported by these documents.

## Smallest safe dependency plan

**A — offline capability probe, first.** Add a non-effect capability result bound to wheel version + source commit + environment/product + command kind + trigger source. Exercise the real pinned OrderFactory/SubmitOrder/adapter with a fake native HTTP boundary and socket-denied Linux, checking SL and TP, both sides, reduce-only, position_idx, IDs, trigger price and source. Test unknown `trigger_by` and MARK_PRICE explicitly. Inspect the public PyO3 callable signature as well. Record `EXPLICIT_TRIGGER_SOURCE_NOT_FORWARDED` if absent; do not compensate with an unrequested SDK fork, arbitrary kwargs, policy downgrade, or direct REST writer. Attached source and standalone source are different capability fields.

**B — typed evidence boundary.** Introduce an offline `ExecutionProvenance`/`OwnedVenueOrderBinding` contract: immutable command ID, actual venue order ID, real execution ID, account-binding reference, source kind, observation cycle/time, and contradictory/unresolved status. Attach children only if authoritative lineage is demonstrable; otherwise preserve `PARENT_LINK_UNPROVEN`. Separate native reconciliation events from actual execution history. Complete-history evidence must carry the queried scope/window and completed pagination, not caller-supplied truth alone. Coordinate this interface with the ongoing history implementation without assuming its state.

**C — native recovery contract, no new server.** Define `NativeRecoveryCheck` returning missing cache IDs, identity mismatches, exact native NETTING mapping, cache-generation mismatch, and unresolved history. Offline test fresh-process restoration of persisted native events/cache and application journal at the same checkpoint, followed by exact cancellation lookup; reject a fresh reconstructed placeholder. Decide between built-in Redis persistence and a separately qualified public-API replay only after that contract test. Future backup/deployment must include native cache generation, application journal, ownership bindings, strategy/trader IDs and version manifest together.

**D — only after A/B/C pass, implement bounded owned repair.** Candidate `OwnedProtectiveRequest` has durable client ID, STOP or TAKE_PROFIT, quantity bounded by currently proved owned net exposure, side, source/price, generation/policy and position_idx=0. Select verified STOP_MARKET / MARKET_IF_TOUCHED conversion, `emulation_trigger=NO_TRIGGER`, reduce-only, and exact native write route. Persist before handoff; an ambiguous submit remains UNKNOWN under the same ID. Require complete fresh readback and no external activity; recompute after fills. Do not cancel previous protection until replacement coverage is independently verified, and do not assume overlapping reduce-only orders are accepted or preserve quantity. No broad cancel, manual adoption or automatic synthetic bracket is implied.

**E — later explicit actual-DEMO observations.** Authenticated UID/subaccount/environment; actual attached-child identifiers and any defensible lineage; trigger-source readback; partial entry/exit coverage; TP and SL activation/fills and fees; cancel/fill races; reconnect history completeness; fresh-process cache restore and same-ID ambiguous recovery; manual-order conflict refusal; flat position plus no residual owned protections. If documented APIs never expose parent proof, observations alone must not invent it: retain that blocker or review a different protection model. Offline green tests authorize none of these live conclusions. Investment controls/FULL_AUTO/ALL_IN_ONE activation remains later work.
