# AI 확정 비용 초과분 보존 계약

`BudgetBook.settle()`은 관측한 실제 비용이 예약 최대값보다 크더라도 전체 비용을 확정 저장한다. 예를 들어 월 한도 `1.00`, 예약 `0.80`, 실제 비용 `0.95`이면 사용액은 `0.95`이며 `0.80`으로 남겨 두지 않는다. 실제 비용이 `1.20` 또는 `100`을 넘더라도 같은 원칙을 적용한다. 실제 비용의 저장은 추가 지출 승인이나 예산 증액을 의미하지 않는다.

## 입력과 정밀도

- 설정 한도와 신규 예약은 기존 계약대로 비음수 일반 십진 문자열, 소수점 이하 최대 8자리, 최대 `100`이다. 신규 예약은 양수여야 한다. 설정의 기본값과 상한은 변경하지 않았다.
- 확정 비용은 별도 파서로 받는다. 정수부 최대 64자리, 소수부 최대 64자리의 비음수 ASCII 일반 십진 문자열을 지원하며, 불필요한 정수 선행 0은 허용하지 않는다. 지수 표기, 부호, 공백, NaN/Infinity, float/bool 및 범위를 넘는 표현은 거부한다. `"0"`, `"150.25"`, `"0.0000000001"`은 지원한다.
- 지원하는 실제 비용은 소수 이하 증거를 버리지 않고 `reservations.actual`에 저장한다. 집계는 각 요청의 실제 비용을 USD `0.00000001` 단위로 올림한 정수로 계산한다. 예를 들어 `0.0000000001`은 집계에서 `0.00000001`이다. 요청별 올림값을 합산하므로 작게 계산하지 않는다.
- 변환, 합계 및 잔여 계산은 정수 연산을 사용하므로 호출자의 Decimal 정밀도나 반올림 설정이 사용액을 축소하지 않는다. 지원하지 않는 비용 증거를 0으로 처리하거나 예약을 해제하지 않는다.

## 영속 보류와 기존 API

기존 요약 필드의 의미와 타입을 유지하고 다음 세 필드만 추가한다. `/api/v1/ai/budget`은 이 요약을 그대로 노출한다.

| 필드 | 의미 |
| --- | --- |
| `overrun_hold` | 모든 기간에서 실제 비용이 예약 최대값을 넘긴 확정 요청이 하나라도 있으면 `true` |
| `overrun_count` | 그러한 요청 수. 현재 월로 제한하지 않음 |
| `overrun_liability` | 그러한 요청들의 **전체 실제 비용** 합계. 초과 차액만의 합이 아니며, 요청별 단위 올림 적용 |

`used`는 현재 UTC 월에 속하는 확정 사용액이다. `reserved`와 `uncertain`은 기존처럼 기간과 무관하게 미확정 최대값을 보존한다. `remaining`은 `max(0, monthly_limit - used - reserved)`라는 금액 계산 결과다. 보류 상태에서는 이 값이 양수여도 신규 유료 예약을 허용하지 않는다. 예를 들어 예약 `0.80`의 실제 비용이 `0.95`이면 잔여 금액은 `0.05`이지만 신규 예약은 실패한다.

보류는 기간이 바뀌거나 설정 한도를 올리거나 다른 요청을 정상 정산해도 해제되지 않는다. 모든 기간의 변경 불가능한 확정 행에서 보류를 계산하므로 재시작 후에도 유지된다. 향후 명시적이고 검증된 대사 절차가 필요하며, 이번 변경에는 해제 기능이 없다. `reconcile()`은 기존과 같이 저장 증거를 조회할 뿐 보류를 해제하지 않는다.

동일 요청의 동일 숫자 비용 정산은 멱등적이다. 표현의 후행 0 차이는 같은 숫자로 취급하지만, 같은 집계 단위로 올림되는 서로 다른 실제 비용도 충돌로 거부한다. 이미 확정된 비용을 더 작은 값으로 덮어쓰지 않는다. `reserve()`의 기존 ID 재조회는 저장 증거만 반환하며 재발송 권한이나 공급자 호출의 멱등성을 보장하지 않는다. 공급자 발송 원장/유료 호출은 이 변경의 범위에 없다.

신규 예약의 요약 확인과 삽입, 확정 비용 변경은 각각 SQLite `BEGIN IMMEDIATE` 트랜잭션 안에서 처리한다. 저장 오류는 성공으로 반환하지 않으며 미완료 변경은 롤백된다. 알 수 없는 비용은 최대 예약액을 유지한다.

## 저장 및 비활성 상태 호환성

기존 두 테이블과 열을 그대로 사용하며 마이그레이션이나 데이터 재작성은 없다. 기존 DB의 `100` 초과 확정 비용도 별도의 실제 비용 파서로 읽는다. 반복 초기화, 과거 월의 초과 비용, 재시작 및 기존 설정 revision 보존을 테스트한다. 임의로 과거 정산 기록을 지우는 행위는 지원되는 대사 방식이 아니다.

`mode=OFFLINE_TEST`, `llm_enabled=false`, `provider_balance=null`, 기존 공급자 미설정 상태를 유지한다. 공급자 통신, API 활성화, UI, 계정, 실제 운영 DB, 키, 유료 생성 및 거래 권한은 변경하지 않는다.

## 검증 범위

회귀 테스트는 `0.80→0.95`, `0.80→1.20`, `100` 초과 비용, 64자리 입력 경계, 재시작/이전 월 보류, 정밀도 독립 올림, 숫자 정산 충돌, 미확정 최대값 유지, SQLite 실패 및 동시 예약을 검증한다. ASGI 테스트는 추가된 예산 필드와 기존 오프라인 설정이 함께 노출되는지 확인한다. 실제 공급자 비용 청구나 유료 발송 검증은 수행하지 않는다.
