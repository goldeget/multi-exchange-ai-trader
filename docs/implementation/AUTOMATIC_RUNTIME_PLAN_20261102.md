# 자동 운용 통합 구현 계획

기준 main: `4f72eeb9671c1507148bf8819ce2056865e55dcb`.
사용자 요청: 최종 자동 매매 프로그램을 병렬 구현·검증하고 GitHub main까지 병합.

## 전역 제약

- FULL_AUTO는 사용자 종목·전략 선택, ALL_IN_ONE은 허용 목록 안의 서버 발급 후보 ID 선택이다. AI는 주문 수치·위험 한도·코드를 생성하지 않는다.
- 실제 사용자 한도, 독립 검증된 거래소 증거, 단일 Nautilus 주문 경로, 실제 체결·보호 주문 확인 없이는 실거래 준비 완료로 표시하지 않는다.
- 외부 수동 포지션·주문은 인수하거나 수정·청산하지 않는다.
- 키·실제 자산·개인 설정 파일을 테스트/하위 에이전트/리뷰/커밋에 노출하지 않는다. 실제 주문·유료 AI 호출·새 서버 생성은 이 구현 검증에 포함하지 않는다.
- 미정 사용자 한도는 0/미설정으로 차단하며 임의 기본 투자금·레버리지를 만들지 않는다. 실제 활성화 제약과 구현 완료를 구분한다.

## 작업과 소유권

1. 실행 경로: 새 execution/runtime.py, execution/venue_readback.py 및 해당 테스트. 기존 journal/risk/protection/native/modes를 사용해 지속 가능한 상태 전이, 체결 후 보호 감시, 재시작·불확실성 처리, 독립 GET 읽기 증거를 구현한다. 실제 qualification을 얻지 못하면 정확한 차단 사유를 유지한다. 기존 shared 파일 변경 필요 시 컨트롤러에 요청한다.
2. AI 경로: 새 ai/generation.py, ai/dispatch.py 및 해당 테스트. OpenRouter 명시 호출, 엄격한 후보 ID 출력, 비용 예약·영속 단일 dispatch·불확실 요금 유지, 무자동 재시도, 비밀 없는 상태를 구현한다. 기존 shared 파일 변경 필요 시 컨트롤러에 요청한다.
3. 운영 경로: 새 execution/state_store.py, 실행 저널 포함 백업/복구 및 deploy/linux·운영 문서·운영 테스트. 큰 단일 JSON 대신 정규화된 상태와 안전한 재시작·백업 계약을 구현한다. 기존 scripts/operations/state_snapshot.py와 운영 테스트만 이 작업이 수정한다.
4. 통합/설정: 컨트롤러가 별도 설정 저장소·상태 API·사용자 화면 및 위 작업의 통합을 맡는다. 입력 미완성 시 명확히 차단하고 시작/일시정지 의미와 실운용 미검증을 표시한다.
5. 계정 바인딩: 별도 account_binding.py에서 실제 GET 인증 메타데이터와 동일 자격증명으로 만든 네이티브 설정을 연결한다. 거래소 UID와 네이티브 계정 라벨을 구별하고, 잘못된 계정·환경·구형 증거를 거절한다. 이 구현도 실제 DEMO 운용 검증을 대신하지 않는다.
6. 각 작업의 명시적 테스트와 독립 리뷰, 전체 위험 검토, 최종 커밋 기준 CI 통과 후 기존 승인에 따라 main 병합.

## 검증

가짜 전송/가짜 시계/격리된 임시 DB로 중복·동시 실행·재시작·타임아웃·부분 체결·미보호·수동 포지션·구형 증거·비정상 응답을 검증한다. 실제 키를 쓰는 전체 앱은 실행하지 않는다. Linux/Nautilus qualification은 독립 실행 환경과 실제 증거가 필요하며 로컬 fake 통과로 대신하지 않는다.
