# 사용자 시작·종료·복구 안내

작성일: 2026-11-01. 현재 저장소의 README와 소스 코드를 읽어 정리한 운영 메모입니다. 이 문서를 작성하면서 프로그램이나 명령을 실행하거나, 실제 DB·키를 열거나, 거래소·AI에 접속하지 않았습니다. 최신 화면 수정의 최종 CI·기준 이미지 승인은 별도 완료 보고서를 확인하세요.

## 시작하기

### 화면 예시만 확인할 때

Node/npm이 준비된 저장소 루트에서 README에 있는 개발 화면 명령을 사용합니다. 아래 명령은 이 문서 작성 중 실행하지 않았습니다.

```sh
npm run dev --prefix apps/web -- --host 127.0.0.1 --port 5173
```

브라우저에서 `http://127.0.0.1:5173/?view=overview&demo=1`을 엽니다. 메뉴 이동 뒤에도 예시 표시가 유지되는지 확인하세요. 이 주소는 개발 서버 전용이며, 배포 빌드에 예시 모드를 보장하지 않습니다. 기존 README의 `preview=1`은 시장 샘플용 옛 주소이므로 전체 화면 예시 안내에는 `demo=1`을 사용합니다.

### 실제 로컬 가상 장부를 사용할 때

검증된 Linux 환경에서만 진행합니다. 먼저 현재 사용 중인 장부·데이터 폴더와 시작 설정을 보존하세요. 다음은 README의 기본 경로 예시입니다. 기존 경로가 다르면 새 빈 장부로 바꾸지 말고 원래 경로를 사용해야 합니다.

최초 준비 시 README의 잠긴 설치 방식은 `uv sync --locked`, `npm ci --prefix apps/web`입니다. 이미 준비된 환경을 불필요하게 다시 설치하지 마세요.

서버는 저장소 루트에서 다음과 같이 시작합니다. 이 구문은 Linux 셸용입니다.

```sh
MARKET_DATA_BLOCKED_HOSTS=fapi.binance.com,api.bybit.com \
PAPER_DB_PATH=work/phase3-data/paper.sqlite3 \
PHASE4_DB_PATH=work/phase4-data/research.sqlite3 \
PHASE4_DATA_ROOT=work/phase4-data/datasets \
uv run uvicorn multi_exchange_trader.main:app --host 127.0.0.1 --port 8000
```

호스트 차단 목록은 README에 보존된 값입니다. 실제 운영 설정에 더 엄격한 기존 차단이 있다면 그대로 유지하세요. 접속 제한을 없애려고 주소·VPN·프록시·인증서 검사를 바꾸지 않습니다.

별도 터미널에서 위의 화면 명령을 실행하고 `http://127.0.0.1:5173/`을 엽니다. 예시가 아닌 실제 로컬 장부 화면에는 `demo=1`을 붙이지 않습니다. 계좌 화면을 열면 선택된 읽기 전용 계좌 조회가 시작될 수 있으므로, 실제 계좌 조회가 필요한 경우에만 열어야 합니다.

서버 응답만 확인하는 README 명령은 다음과 같습니다.

```sh
curl -fsS http://127.0.0.1:8000/api/v1/health
```

응답이 와도 거래소 접속이나 자동 진행이 정상이라는 뜻은 아닙니다. 화면의 진단·복구와 아래 읽기 주소를 함께 확인하세요. 이 메모에 주문·명령 POST 예시는 넣지 않았습니다.

| 확인할 내용 | 읽기 주소 |
|---|---|
| 기능별 준비 상태 | `http://127.0.0.1:8000/api/v1/ready` |
| 지원 범위·네이티브 사용 가능 여부 | `http://127.0.0.1:8000/api/v1/capabilities` |
| 장부별 현황 | `http://127.0.0.1:8000/api/v1/overview` |
| 등록 여부·권한 미검증 상태 | `http://127.0.0.1:8000/api/v1/connections/status` |
| 자동 작업·장부·미완료 요청 | `http://127.0.0.1:8000/api/v1/diagnostics` |

새 가상 실행은 생성만으로 자동 시작하지 않습니다. 대상과 고정 설정·장부를 확인한 뒤 사용자가 명시적으로 재개해야 합니다. 자격 등록이나 지원 표시만으로 실행 버튼을 눌러도 안전하다고 판단하지 마세요.

## 일시정지와 종료

| 조작 | 처리 의미 |
|---|---|
| 신규 진입 일시정지 | 새 가상 진입을 막으면서 봉 처리와 기존 가상 포지션 관리를 계속합니다. V2 실행 대상입니다. |
| 전체 일시정지 | 봉 처리와 기존 가상 포지션 관리도 멈춥니다. 포지션을 닫는 기능은 아닙니다. |
| 가상 포지션 정리 후 종료 | 선택한 가상 실행을 검토한 뒤 해당 장부의 포지션 정리와 종료를 요청합니다. 다른 장부나 실제 거래소 포지션을 정리하지 않습니다. |
| 서버 프로세스 종료 | 프로그램을 멈춥니다. 그 자체가 가상·실제 포지션을 모두 닫았다는 뜻은 아닙니다. |

정상 종료 순서는 다음과 같습니다.

1. 새 요청을 더 누르지 말고, 실행 중인 요청의 결과 또는 미확정 안내를 확인합니다. 보유 가상 포지션을 정리하려는 경우에만 화면의 정리·종료 검토를 사용합니다.
2. 서버를 실행한 터미널에서 정상 종료 신호인 Ctrl+C를 한 번 보내고, 종료가 끝나 터미널 입력 상태로 돌아올 때까지 기다립니다. 종료 중인 저장을 강제 취소해 되돌렸다고 간주하지 않습니다.
3. 화면 개발 서버도 실행한 터미널에서 Ctrl+C로 종료합니다. 브라우저 탭만 닫으면 서버는 계속 실행될 수 있습니다.
4. 종료가 끝난 뒤 장부·데이터·설정의 보존 사본을 관리합니다. DB를 지우거나 새 DB를 만들어 종료 문제를 숨기지 않습니다.

종료가 멈췄거나 오류가 났다면 원본을 보존하고 미확정 상태로 취급하세요. 강제 종료·전원 차단·디스크 오류에서도 항상 무손실이라고 보장하지 않습니다.

## 재시작과 미확정 요청 복구

1. 같은 코드 버전, 원래 DB·데이터 경로, 같은 브라우저 프로필과 화면 주소를 사용합니다. 브라우저 저장소는 주소·호스트·포트별로 나뉩니다. 예를 들어 5173과 시험용 4174의 기록은 서로 다릅니다.
2. 진단에서 자동 작업이 살아 있는지, 저장된 처리 위치가 진행했는지, 미완료 주문 확인이나 DEMO 결과 불확실 항목이 있는지 읽습니다. 숫자를 읽지 못한 상태를 0건으로 해석하지 않습니다.
3. 실행 중 재시작한 자동 실행은 PAUSED_RECOVERY로 보존되며 자동 재개하지 않습니다. 신규 진입 정지 상태도 재시작 후 명시적 확인이 필요합니다.
4. 응답을 못 받은 요청은 미적용으로 단정하지 않습니다. 화면에 보존된 같은 요청 키·같은 내용으로 기존 결과를 대조합니다. 새 검토·새 키로 반복 제출하거나 브라우저 기록을 지우지 않습니다.
5. 원장 버전·자료 검사·네이티브 재계산이 맞지 않거나 저장소가 손상됐다고 나오면, DB·데이터·브라우저 기록을 그대로 보존하고 원인을 확인합니다. 원본을 초기화하는 복구 절차는 제공하지 않습니다.
6. 확인이 끝난 실행만 사용자가 명시적으로 재개합니다. “서버 응답 정상”이나 예전 RUNNING 표시만으로 자동 진행이 살아 있다고 판단하지 않습니다.

Bybit DEMO의 결과 불확실·감축 실패는 별도로 다룹니다. 서버는 시도 전에 기록을 남기며 같은 추천 기록 저장소의 새 시험을 차단합니다. 기존 접수 기록을 보존하고 실제 연습계좌 결과를 대조해야 합니다. 자동 재전송·자동 추가 정리·불확실 기록 초기화 기능은 제공하지 않습니다. 서로 다른 프로그램·별도 DB가 같은 거래소 계좌를 쓰는 경우까지 이 잠금이 조정하지는 않습니다.

DB와 함께 있는 -wal·-shm 파일, 기존 work 폴더, 자료의 체크섬·설정·감사 기록과 백업도 보존합니다. 브라우저의 미완료 요청 기록은 paper-pending-command-v1, spot-paper-pending-v2, phase4-uncertain-intent-v1입니다. 이 항목에 비밀키를 넣거나 오류를 없애려고 삭제하지 않습니다.

키는 로컬 환경 또는 허용된 .env 설정에서만 취급합니다. 문서·대화·스크린샷·공개 Git에 넣지 않습니다. 내부 AI 예산을 바꾸어도 실제 제공자 잔액이 생기거나 외부 AI가 연결되는 것은 아닙니다. 비용 결과가 불확실하면 예약을 유지하는 구조입니다.

## 대화 중단과 실제 휴대전화 접속의 한계

장부 복구와 이 ChatGPT/Codex 대화 복구는 다른 범위입니다. 제품은 이 대화의 내용·에이전트의 생각·작업 순서나 도구 세션을 자동 복원하지 않습니다. 대화가 끊긴 뒤에는 저장된 저장소·브랜치·커밋/PR, 작업 메모, 원래 데이터 경로와 미완료 요청 상태를 근거로 다시 확인해야 합니다. 이 메모를 남겼다는 이유로 대화 기억이 영구 보장되거나 미완료 작업이 자동 재개되지는 않습니다.

현재 휴대전화 관련 검증은 화면 폭과 조작을 브라우저에서 확인하는 범위입니다. 실제 휴대전화, 외부망, 원격 로그인·암호화·인증·공개 배포를 구성하거나 검증하지 않았습니다. loopback 바인딩을 유지하며, 접속을 위해 임의로 0.0.0.0으로 열거나 보안 경계를 낮추는 절차는 안내하지 않습니다.

## 검증 근거와 남은 확인

최신 네이티브 합격 근거는 **CI5, 코드 feda6c25, [실행 41272013569](https://github.com/goldeget/multi-exchange-ai-trader/actions/runs/41272013569)**입니다. 상위 검증 보고에 따르면 5개 작업이 모두 통과했으며 Python 492개 시험·28개 하위 검사, Ruff, mypy 63개 파일, 프런트엔드 120개 시험을 확인했습니다. 브라우저는 90개 통과·좁은 화면 중복 24개 의도적 제외였으나 **이미지 후보를 만드는 capture-only 실행**이므로 승인된 기준 이미지와 엄격 비교를 통과했다는 뜻은 아닙니다. 후속 CI6에서 수정된 오프라인 화면을 다시 캡처·검토할 예정입니다.
