# 네이티브 제어·체결 이력 통합 계획

선행 자동 운용 상태 변경 위에서 실제로 빠져 있는 주문 제어·회계 경로를 구현한다. 실제 운용 금액·한도·서버 비용은 미정이며 실제 주문·유료 생성·서버 생성은 수행하지 않는다.

1. 네이티브 제어: 핀 고정된 Nautilus 경로로만 소유 주문 취소와 레버리지 적용을 수행하는 코드 및 영속 의도·불확실 상태·독립 읽기 확인을 연결한다. ACK는 실제 적용·취소·체결 없음의 증거가 아니다. 수동/외부 주문·포지션에는 손대지 않는다. 레버리지에는 최신 사용자·거래소 범위와 외부 노출 없음이 필요하다. 지원하지 않는 분수 레버리지를 임의 반올림하지 않는다.
2. 이력·회계: GET 전용 클라이언트에서 체결·주문·거래내역·위험한도 자료를 엄격히 읽고 범위·페이지·숫자·중복을 검증한다. 포지션·주문 소유권 매핑과 일일 순실현 손실(수수료·펀딩 포함)을 연결할 수 있는 명시적 계약을 구현한다. 완전한 페이지 조회와 실제 사건의 완전성을 구분한다. 누락·알 수 없는 유형·모호한 현금 흐름은 차단하며 0으로 추정하지 않는다.
3. 컨트롤러 통합: 계정 세션·작업자·현재 위험 판단·보호 주문·이력을 단일 작업자에 연결한다. 워커 시작 자체로 qualification을 해제하지 않는다. 프로덕션 활성화에 남은 코드와 실제 검증을 정확히 기록한다.
4. 각 작업과 전체 브랜치를 독립 리뷰하고 최종 Linux CI를 통과한 변경만 기존 사용자 승인에 따라 main에 병합한다.

비밀 파일·실제 DB를 하위 에이전트가 읽지 않는다. 테스트는 가짜 전송과 격리된 저장소에서 수행한다. 현재 승인된 계정·모드·종목·위험 한도를 넘어서는 동작을 새 코드의 기본값으로 만들지 않는다.
