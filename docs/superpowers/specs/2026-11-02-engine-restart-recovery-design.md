# Engine restart recovery from a sealed local generation

Date: 2026-11-02. Base: `e6805521601865ea6a24512ae8cda1e9dadeae63` (PR #21).

## Intended outcome

Restore genuine pinned Nautilus engine orders, order-to-position indexes and actual Position objects into a new unconnected worker from a complete clean-stop generation. Preserve application command uncertainty and liabilities. This is local restart recovery, not exchange reconciliation or execution qualification. No automatic resend, synthetic acknowledgement, fill credit, terminal confirmation, flat confirmation or reservation release follows from restoration.

The previous history-only fill-credit feature is complete and remains unchanged. Current `NativeBybitBridge.register_owned` restores an application dictionary only. Current `native_recovery.py` is a diagnostic accepting caller checkpoint labels and cannot be used as proof of durable restoration. Native NETTING position IDs are `instrument_id + '-' + strategy_id`, unlike application position IDs.

## Authority and scope

The user authorizes implementation, independent subagent review, validation and main merge when passing. Actual exchange orders (including DEMO), paid application AI calls and additional server expenditure are forbidden. Use synthetic temporary stores and an isolated native Linux contract harness only. Do not inspect operator secrets, environment files, databases or logs. Do not add Redis, dependencies or services. Preserve previous worktrees and handoff artifacts. Keep the fixed qualification rejection, policy STOPPED, Bybit DEMO/LINEAR scope, pinned `nautilus-trader==1.231.0`, and all financial/provenance safeguards.

## Chosen recovery model

Use a bounded private local JSON generation (`native-restart.json`) outside existing SQLite schemas. Publish by restrictive temporary file, flush/fsync and atomic replacement. A canonical digest binds the full logical contents of `execution.sqlite3`, `runtime-state.sqlite3` and `history.sqlite3` (including inboxes, audits, projections, reservations, scope and schema) to the native payload and exact worker identity. SQLite WAL/header layout is not part of the logical digest, so an offline backup/checkpoint does not change it. Read through safe read-only SQLite handles, never immutable mode that ignores live WAL. Validate source paths and bounded content; reject symlinks, junctions, hardlinks, duplicate JSON keys, unknown fields, non-finite numbers and truncated/oversized data with fixed redacted errors.

Identity includes application account/environment, BYBIT native account label, trader, strategy, exact instrument allowlist and pinned native version. Generation and channel identity are distinct: every restarted assembly gets a new channel and lease. Hashes protect accidental corruption, not malicious alteration by someone controlling the private state directory.

The file has an explicit sealed/active lifecycle. A sealed generation is validated against current application contents before runtime startup recovery mutates anything. After full native decode/semantic validation and before any mutation or native connection, atomically consume the seal into active state. An active, stale, partial, mismatched or unsupported generation fails closed on restart. Never fall back to an older file. A new empty application may bootstrap with an empty fresh native cache; an existing application without a matching seal cannot be represented as successfully restored.

A clean stop sets the existing sticky admission fence, settles admitted operations, stops the actual producer, proves engine disconnection/empty queues, closes its event channel and drains posted callbacks. It then marks transport loss and preserves UNKNOWN, captures actual cache objects and current application digest while holding the same scoped OS lease, publishes the sealed generation, and only then disposes/releases ownership. Failed quiescence or serialization never publishes a clean seal. A crash during an active generation is deliberately blocked. Arbitrary-crash recovery requires a future durable native write-through/event log or fresh authenticated reconciliation; this feature must report that limitation explicitly.

## Genuine native payload and validation

Serialize only actual pinned native cache objects through audited pinned SDK serializers/public restore APIs. Persist complete actual order events/state, original event IDs/timestamps and genuine instrument definitions required to rebuild Position objects. Restore original events into objects/cache only; never feed historical replay through `consume_native`, the message bus, journal ACK paths or fill-accounting paths. Do not manufacture OrderSubmitted/Accepted/Filled events from application or Bybit history records. Preserve actual INITIALIZED, pending-cancel and terminal states without interpreting them as authority; reject unsupported types/states instead of dropping records.

Inspect all native orders, all native positions and all order-position links. Every native order must match an immutable durable ENTRY/EXIT request, exact native types, trader/strategy/account/instrument identity, side, quantity, price, reduce-only and venue identity where known. Foreign/manual objects cause a fixed blocker without exposing their IDs. Missing native objects for a pending or unresolved command do not prove the command was never sent; that command remains unresolved and cannot be resent. An accepted cache entry cannot promote UNKNOWN.

Position restoration must recreate actual Position objects and verify cache indexes, not merely an order-to-position label. Persist/replay original native fill events and the exact native instrument; compare reconstructed Position state with the saved state and verify all fills belong to durable owned orders. Preserve position identity and lifetime/opening-order identity. Reject ambiguous overlapping application positions on one NETTING instrument, inconsistent links, foreign exposure, missing instruments/fills and unsupported multiple position lifetimes instead of merging unrelated positions. Position data is local cached exposure, not fresh venue proof.

Decode and validate the complete candidate in isolation before touching the target cache. Restore into an empty fresh cache only; verify actual cached objects and indexes afterward. On failure dispose the new assembly and keep startup blocked; no partially populated assembly may connect or be admitted. In-memory native cache hydration must not be cleared by the pinned startup `load_cache()` lifecycle. Automatic native reconciliation can infer fills, even with missing-order generation disabled; it must not run as authority or silently modify a restored generation. For this feature, monitoring connection after a restored generation remains explicitly blocked until a separately reviewed reconciliation lifecycle exists. Passive runtime/history inspection may be available only after successful local restoration. No new live connection is executed during development.

## Application integration and uncertainty

Validate application replay/immutable ownership before restoration and before SENDING-to-UNKNOWN recovery. Add a narrow internal runtime startup recovery seam rather than duplicating replay reducers or allowing an alternate weak validator. After successful restore perform existing startup transitions: SENDING becomes UNKNOWN, projections require reconciliation and old freshness/readbacks are not renewed. CANCEL and LEVERAGE UNKNOWN remain unchanged; their effects are never repeated. Diagnostics distinguish fresh empty cache, restored local cache, missing native objects and blocked generation, and always report `production_supported=False`.

Original app DB schema/history codecs, execution-credit guards and history V1/V2/V3/V4 semantics stay intact. Existing fake-assembly tests stay useful but cannot qualify genuine native restoration. A valid local restore does not remove the fixed execution gate or enable signal/plan producers, protective child repair, whole-account flatness or continuous unattended trading.

## Backup and acceptance

Extend the offline standard-library snapshot tool with a new manifest version 4 for native-bearing generations, explicit `native_files`, and `--require-native`. Native data requires complete runtime and history ledgers; require a sealed file whose application logical digest matches the restored/copied data. Include native data automatically if present; never silently omit active/stale/malformed native state. Preserve exact v1/v2/v3 reading/writing behavior when no native file exists. Backups remain unsigned private offline recovery artifacts, not exchange proof.

Acceptance includes meaningful RED/GREEN pure tests; actual pinned Linux order/Position/cache round-trip; a fresh-worker clean-stop to backup/restore to fresh-worker/cache round trip; SENDING/UNKNOWN entry/cancel/leverage and reservations unchanged except established SENDING-to-UNKNOWN recovery; no fake ACK/credits; actual pending/closed state fidelity; missing/stale/active/partial/mixed generation refusal before application mutation; lease/channel identity; foreign/manual/ambiguous NETTING rejection; corruption and atomic publication failure; and v1-v3 compatibility. Add a separate network-isolated native restart contract module and explicit count/no-skip check. Keep the existing strict 36-case native gate exactly intact. Final gates are independent task and whole-branch review, full exact-head hosted CI, main merge pinned to that head and postmerge readback/CI. Preserve evidence and report verified, unverified and remaining work separately.
