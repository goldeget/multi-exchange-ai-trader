| 후속 `execution/risk_v2_codec.py` | 새 닫힌 persistence schema와 compact pin 직렬화 | V1 payload 자동 변환, import path/eval, raw catalog 내장 |

의존 방향은 `risk_v2_math → stdlib`, `risk_v2_contracts → shared product/A02/modes + math`, `linear_risk_evidence_v2 → contracts + math`, `linear_risk_v2 → contracts + evidence + math`다. evidence가 calculator를 역으로 import하지 않는다. mark coverage/quantity 합계의 작은 내부 helper를 contracts에 두고 valuation/tier가 재사용한다. V1 helper/두 번째 source parser/추가 계산 engine을 만들지 않는다.

첫 순수 PR에서 V1 math를 추출하지 않는다. 기존 `_record`/`_precision`의 계약과 회귀를 보존하고 V2는 §5A의 작은 exact 산술 module 하나를 사용한다. V1 전체 복제, fake finite cap, entry=mark 변환은 금지한다. 작은 scalar 개념 중복의 비용을 수용하며 향후 공통 추출은 별도 parity PR이다. 수집자·margin model·coordinator를 복제하지 않는다.

## 5. 타입과 validation 공통 계약

아래 모든 필드는 필수이며 default가 없다. frozen dataclass는 관찰 값의 container일 뿐 authenticity가 아니다. 공개 함수는 exact class/field/container를 다시 검사하여 `object.__new__`, 누락/변조 field, subclass, mutable container, 임의 equality/repr/tz hook에 의존하지 않는다.

- exact Decimal·finite·source 입력 256 digits 이하, exponent 절댓값/adjusted 절댓값 1000 이하를 precision 할당 전에 검사한다. A02 DecimalField는 원래의 더 좁은 64 digits/32 fraction 규칙을 그대로 검증한다. 이 수치는 기술 자원 경계이며 금융 한도가 아니다. derived 계산은 source 256-digit 제한으로 다시 잘라내지 않는다.
- Decimal 입력을 float/int/bool/str에서 암묵 변환하지 않는다. 양수 가격/수량/한도, nonnegative 비용·잔량·손실을 명시한다. **모든 금융 floor/grid/predicate/product/sum은 §5A의 exact Fraction/int만 사용한다.** Decimal context의 나눗셈/반올림 값으로 금융 판정을 하지 않는다. 예상 산술/resource 예외만 고정 code로 닫는다.
- policy의 leverage/per_trade_loss/daily/drawdown/total risk/total margin/allocation/max count는 strictly positive이고 leverage_min<=leverage_max다. liquidation_buffer_fraction은 0 이상 1 미만, quote/evidence age는 0 이상이다. account equity는 양수, available margin/aggregate risk·margin/loss/drawdown/count와 reservation totals는 0 이상이다. 비용 0은 명시 관찰값으로만 가능하며 unknown fee/funding의 기본값이 아니다.
- 시간은 exact datetime, exact standard `datetime.timezone` tzinfo를 받아 UTC로 정규화한다. naive/custom/subclass/ZoneInfo는 V2 경계에서 거절한다. V1의 UTC fold 지원은 바꾸지 않는다. datetime/TTL 값은 호출자가 명시하며 시계를 읽거나 TTL을 발명하지 않는다. `server_observed_at <= received_at <= now`; 만료는 `now >= valid_until`에서 차단한다. quote/evidence age는 명시 policy 값과 비교한다.
- 실제 source 관찰은 RiskObservationRefV2의 server/received 시각을 사용한다. 계산 결과는 별도 RiskComputationRefV2.computed_at을 사용하며 존재하지 않는 server 시각/transport를 만들지 않는다. computed_at<=now이고 명시 evidence age 안이어야 하며 underlying source freshness는 별도로 모두 검사한다. computed_at만 갱신해 오래된 source를 fresh로 만들지 않는다.
- computed_at은 **그 결과에 실제로 소비한 bound 입력을 모두 받은 뒤 로컬 평가를 마친 시각**이다. §5B의 하한을 함께 만족해야 한다. 동일 clock tick에서 input receipt와 completion이 같을 수 있으므로 모든 논리 timestamp 비교는 `<=`/`>=`다. 실제 operation의 선후/issuer 독립성은 timestamp equality만으로 입증하지 않는다.
- 일반 revision/ID는 ASCII `[A-Za-z0-9][A-Za-z0-9_.:/-]{0,95}`, SHA256은 lowercase 64 hex다. 실제 account ID는 기존 ProtectionScope의 1..256 무제어문자/공백 규칙을 재검사한다. 문자열/source label은 transport 증명이 아니다.
- 수집자는 timestamp·raw/source hash와 의미 revision을 따로 보관한다. A02 observation은 `validate_instrument_observation()`로 매번 검증하며 catalog 선택/freshness는 `require_catalog_selection()`의 정확한 명시 인자로 먼저 확인한다. V2 함수가 A02 internal canonical parser를 복제하지 않는다.
- 로컬 자원 상한: 입력 exposure components 각 tuple 0..1024, marks 1..100, tier rows 1..1024. count는 exact int/nonnegative, policy max count는 positive. 상한 초과 시 누락/샘플링하지 않고 `RISK_V2_RESOURCE_LIMIT`이다. 현재 계좌가 더 크면 지원 범위 밖으로 차단하며 이것을 거래소 한도라고 쓰지 않는다.
- account/reservation components는 `(instrument.venue,product,symbol,component_id)` 순, marks는 key 순, tier는 lower range 순으로 정렬한다. mark keys는 모든 account/reservation/proposed key와 정확히 같아야 한다. component ID 중복·두 집합 간 동일 ID는 산술 전 거절한다. 서로 다른 ID가 같은 실제 주문을 가리키는지, ACK된 주문이 두 집합 어디에도 빠졌는지는 실제 producer가 native ID/venue ID와 대조해야 하며 local ID uniqueness만으로 입증하지 않는다.
- `RiskV2Rejected(ValueError)`는 허용된 고정 `.code` 한 개만 노출한다. provider/계좌 원문·key·unknown 값·repr·URL·연산 내용을 error 문자열에 넣지 않는다. 예상 parse/overflow 예외만 `from None`으로 번역하며 예상 밖 오류를 성공으로 바꾸지 않는다.

whitelist 밖 code의 RiskV2Rejected constructor 호출은 고정 `ValueError("INVALID_RISK_V2_REJECTION_CODE")`다. A02 CatalogRejected는 V2 public boundary에서 원문 없이 `RISK_V2_INPUT_INVALID`로 번역한다.

## 5A. S4 — 실행 가능한 exact 산술과 결정적 표시 계약

금융 산술의 내부 표현은 stdlib `Fraction`과 Python arbitrary-precision int다. 이 module은 계산의 작은 공용 도구이며 margin model/venue grid 자격을 발급하지 않는다. public V2 boundary가 source 타입/표현/범위를 먼저 검증한다. low-level math 실패는 고정 `RISK_V2_INPUT_INVALID` 또는 `RISK_V2_RESOURCE_LIMIT`로 번역한다.

Fraction helper 입력도 exact Fraction이고 numerator/denominator는 exact int, denominator>0이어야 한다. subclass/hooks/bool을 받지 않는다. 작업 한도를 검사한 뒤 Fraction(numerator,denominator)로 기약화하여 forged/unreduced 내부 값을 정규화하거나 고정 오류로 거절한다. 원천 Decimal의 표현은 이 내부 정규화와 별도로 보존한다.

```python
def decimal_fraction_v2(value: Decimal) -> Fraction: ...
def finite_decimal_v2(value: Fraction) -> Decimal: ...
def decimal_text_v2(value: Decimal) -> str: ...
def floor_ratio_v2(numerator: Fraction, denominator: Fraction) -> int: ...
def ceil_ratio_v2(numerator: Fraction, denominator: Fraction) -> int: ...
def floor_quantity_v2(loss_budget: Fraction, unit_loss: Fraction, step: Fraction) -> Fraction: ...
def zero_origin_lattice_v2(lower: Fraction, upper: Fraction, step: Fraction) -> tuple[Fraction, Fraction]: ...
def is_zero_origin_member_v2(value: Fraction, *, first: Fraction, last: Fraction, step: Fraction) -> bool: ...
def display_ratio_v2(numerator: Fraction, denominator: Fraction) -> Decimal: ...
```

정확 알고리즘은 다음과 같다.

1. `decimal_fraction_v2`: exact finite Decimal의 `(sign,digits,exponent)=as_tuple()`를 읽는다. coefficient는 digits를 `coefficient=coefficient*10+digit`으로 접어서 만들고 `int(str(...))`를 쓰지 않는다. zero는 Fraction(0,1). exponent>=0이면 signed coefficient×10**exponent/1, 음수이면 signed coefficient/10**(-exponent)로 Fraction을 만든다. source spelling/sign/scale은 source DTO에 그대로 남고 이 변환은 계산용이다.
2. `floor_ratio_v2(N,D)`: N>=0, D>0에서 `(N.numerator*D.denominator)//(N.denominator*D.numerator)`다. ceil은 같은 positive integer 분자 a/분모 b에 `(a+b-1)//b`다. Decimal division을 전혀 하지 않는다.
3. `floor_quantity_v2(B,U,S)`: B>=0,U>0,S>0. n=`floor_ratio_v2(B,U*S)`, Q=n*S. 반드시 **Q>=0, Q/S exact integer, Q*U<=B<(Q+S)*U**다. 금융 수량을 바꾸는 후처리 rounding/clamp가 없다. minQ 미만이면 상위 assessor가 거절한다.
4. `zero_origin_lattice_v2`: rule=`LOCAL_ZERO_ORIGIN_LATTICE_V1`, n_first=`ceil_ratio_v2(lower,step)`, n_last=`floor_ratio_v2(upper,step)`. lower/upper/step>0, lower<=upper와 n_first<=n_last를 요구한다. first=n_first*step, last=n_last*step. membership는 first<=L<=last 및 `L/step`의 **정확 정수성**이다. Fraction의 분모가1인지 보거나 정수 나머지를 검사한다.
5. 금융 cap/loss/margin/cost/tier/stop/tick/qty/leverage의 products/sums/comparisons는 전부 Fraction/int다. 예를 들어 liquidation buffer는 gap>0와 **gap>=policy_buffer*entry_limit**를 exact 비교하고 `gap/entry_limit` 표시값으로 판정하지 않는다. account/예약 합계, mark gross, minimum Q×evaluation_price, reserve max, 일일손실/낙폭도 동일하다.

   freshness의 Decimal seconds도 exact Fraction으로 해석하고 integer age_microseconds와 max_age_seconds×1,000,000을 비교한다. 실제 model의 비종결 금융 산식은 exact rational을 유지하고 M1에서 입증한 경제적 단위/rounding으로만 유한 관찰값을 만들 수 있다. 표시용 CEILING80을 fee/margin의 금융 rounding 규칙으로 전용하지 않는다. 단위/rounding 근거가 없으면 actual model gate가 실패한다.
6. `finite_decimal_v2`: reduced Fraction의 양수 denominator를 2와5로 나눠 a,b를 센다. 남은 denominator가1이어야 한다. k=max(a,b), C=abs(numerator)×2**(k-a)×5**(k-b). C의 digits는 repeated integer divmod로 만들며 `str(int)`, `Decimal.scaleb`, ambient normalize/quantize를 사용하지 않는다. `Decimal((sign,tuple(digits),-k))`로 **정확히** 재구성한다. denominator1인 정수는 exponent0, zero는 positive Decimal tuple `(0,(0,),0)`다. source representation을 이 derived 규칙으로 덮어쓰지 않는다.
7. nonterminating quotient는 금융 predicate에 없다. `display_ratio_v2`는 denominator>0인 비음수 표시만 지원한다. Fraction이 finite-decimal이면 위 exact reconstruction을 반환한다. 그 밖에는 fresh `Context(prec=80,rounding=ROUND_CEILING,Emin=-999999999,Emax=999999999,capitals=1,clamp=0,flags=[],traps=[InvalidOperation,DivisionByZero,Overflow])`의 `divide(exact_numerator_decimal,exact_denominator_decimal)`를 사용한다. Inexact/Rounded 등 나머지 trap은 명시 false다. ambient precision/rounding/traps/flags를 읽거나 바꾸지 않는다. 이 규칙의 이름은 **`RISK_V2_EXACT_FINITE_ELSE_CEILING80_V1`**다.

8. `decimal_text_v2`는 canonical/durable Decimal 문자열도 ambient capitals/formatting에 의존하지 않게 한다. exact tuple에서 digit 문자는 각0..9를 ASCII 문자로 이어 만든다. adjusted=exponent+len(digits)-1, point=len(digits)+exponent다. exponent<=0이고 adjusted>=-6이면 point 위치에 소수점을 넣거나 앞에0/필요한0을 붙이는 fixed notation, 나머지는 첫 digit+나머지 mantissa+대문자E+signed adjusted의 scientific notation이다. sign/zero/trailing zeros/exponent를 그대로 복원할 수 있게 보존한다. 작은 bounded exponent int만 문자열화하고 coefficient int/Decimal의 str/format/ambient normalize는 쓰지 않는다. A02 raw wire spelling은 원래 raw field에 별도로 보존한다. 예: source100.0→`100.0`, source1E3→`1E+3`, source0.00→`0.00`, source-0E3→`-0E+3`.

80 significant 표시값은 비종결 양수 exact ratio보다 작지 않으며 오차는 표시 마지막 자리 단위보다 작다. display 값/그 값을 float로 바꾼 값으로 승인·grid·tier·수량·margin/buffer를 결정하지 않는다. `estimated_loss_fraction_display`는 이 규칙으로만 생성한다. source Decimal의 256-digit 경계는 source 입력에만 적용하며 derived 값/digest 재검증에 적용하지 않는다.

validator도 field 역할을 구분한다. policy/원시 가격·수량·funding_rate 등 source fields에는 원래 source256/1000 한도를 유지한다. sizing의 distance/unit_cost/unit_loss/Q/loss/cost/funding, valuation 금액, tier U/계산된 grid endpoints, preparation capacity/display, final reserve, SpotCash/Base 결과는 derived 검증이다. cost의 계산된 per-base allowance, model의 initial_margin/venue reserve/liquidation output, ledger/예약의 aggregate risk·margin/loss/drawdown totals도 이미 계산된 관찰값이므로 source256 한도를 재적용하지 않는다. 타입/finite/경제적 부호/정확 결속과 derived 작업 한도/64KiB hash는 검사한다. 원천 parser는 원래 raw field의 더 좁은 한도를 유지한다. 이 구분은 모든 generated record를 다시 digest/assessor/codec에 넣을 때도 동일하다.

자원 한도도 수학과 분리한다. 내부 Decimal→rational 변환은 finite exact type 뒤에 derived coefficient digits/exponent 절댓값 65536과 정수 작업 bit_length 1,000,000을 기술 한도로 검사한다. power allocation 전에 지수/보수적 bit upper bound를 검사하고, 정수 연산 직후 numerator/denominator bit_length를 검사한다. 이 수치는 금융 cap이 아니다. source의 더 좁은 256/1000 및 A02 64/32 규칙은 public source boundary가 먼저 검사한다. digits 추출은 65536을 넘으면 중단하며 최종 canonical payload 64KiB를 그대로 적용한다. Python int-string 전역 제한을 변경하지 않는다.

**반드시 고정할 literal 예:**

- 12/7의 display는 exact `Decimal("1." + "714285"*13 + "8")`(80 significant, 마지막 자리 위로)다. 이 근삿값은 loss/equity 표시이고 어떤 판정에도 들어가지 않는다.
- U=12,S=.1,B=`1.2-1E-200`, `1.2`, `1.2+1E-200`에서 helper Q는 각각 0,.1,.1이다. B=`14-1E-200`/U7/S1이면 Q1, B14이면 Q2다. quotient rounding으로 한 unit 올리면 실패다.
- source Decimal `1E+1000`과 `1E-1000`의 exact 합은 coefficient digits2001, exponent-1000인 Decimal tuple이다. 이를 generated result→digest→최종 재검증에 통과시킨다. source field로 같은 2001-digit spelling을 넣는 것은 source 표현 한도로 실패한다.
- 5001-digit integer를 내부 derived reconstruction fixture로 주어도 `str(int)` 제한에 의존하지 않고 64KiB 안이면 처리한다. 이를 실제 source/금융 seed로 넣지 않는다.
- ambient prec1/ROUND_UP/ROUND_DOWN/ROUND_HALF_EVEN, Inexact/Rounded trap true, 작은 Emax/Emin, capitals0/1, 임의 기존 flags에서도 같은 exact 결과/거절 code/display/canonical string이어야 한다. ambient context는 호출 전후 동일해야 한다.

## 5B. S1 — source→cost/minimum→margin→liquidation 시간 DAG

`computed_at`은 local evaluation **완료** 시각이다. source.received_at은 로컬 수신 완료 시각이고 reservation.observed_at은 bound 로컬 snapshot 완성 시각이다. future schedule인 next_funding_at/holding_until/valid_until을 완료시각 하한으로 잘못 사용하지 않는다. now freshness와 아래 causal lower bound를 모두 검사한다. 동일 시각은 허용한다.

| 결과 | 순수 함수가 제공된 field로 검사하는 완료 하한 | 실제 issuer가 추가로 입증할 것 |
|---|---|---|
| cost | cost.computed_at>=max(fee.received_at,funding.received_at,instrument.source.received_at), computed_at<=now | origin_quote_id, gap model/다른 실제 소비 source·computation의 완료/수신시각과 내용. ID에서 시간을 추측하지 않음 |
| minimum | minimum.computed_at>=instrument.source.received_at, computed_at<=now | input_observation_ids 전체를 actual registry/source records로 resolve해 각 receipt/computation 완료<=minimum.computed_at. 누락/다른 내용/미해결 ID면 실제 admission 거절 |
| margin | computed_at>=max(cost.computed_at,minimum.computed_at,account.reference.received_at,reservations.observed_at,모든 mark.reference.received_at,tier.reference.received_at,instrument.source.received_at), computed_at<=now | actual model이 소비한 held-domain source/readback/계산 input 전체도 같은 하한. private source registry/current producer가 정확 입력과 hash를 대조 |
| liquidation | liquidation.computed_at>=margin.computed_at, computed_at<=now | margin hash에 실제로 결속된 계산을 소비했음, 추가 venue/model source가 있으면 각각 receipt/computation 완료<=liquidation.computed_at |

cost와 minimum은 서로 선후관계를 요구하지 않는 병렬 입력이며 둘 다 margin의 선행이다. `LinearSizedEntryV2.assessed_at`, `LinearAdmissionValuationV2.assessed_at`, assessor의 새 audit `assessed_at=now`는 source receipt나 새로운 경제 computation이 아니므로 위 max에 **넣지 않는다**. 같은 underlying inputs/경제 digest로 now+1microsecond 재검사할 때 기존 유효 margin/liquidation을 자기 무효화하지 않는다. 원천 receipt/내용/computation 자체가 바뀌면 hash와 DAG를 새로 평가한다.

이 stage 계약에서 cost/minimum이 소비하는 instrument는 `inputs.instrument`의 정확 observation/pin이다. semantic revision 문자열만 같은 다른 receipt를 소비한 결과로 재라벨하지 않는다. actual issuer는 computation input hash/보관된 원천 객체가 그 정확 pin을 포함하는지도 검사한다. 이 때문에 새로운 instrument receipt로 실제 input bundle을 바꾼 경우와 audit assessed_at만 바꾼 경우의 재사용 규칙이 다르다.

readback의 순수 논리 검사는 `after_control_at<=readback.server_observed_at<=readback.received_at`, `readback.server_observed_at<=account.server_observed_at`, `readback.received_at<=account.received_at<=now`와 supplied side/leverage/mode/account ID/digest 일치다. timestamp equality는 허용한다. 이 식은 **실제 control 완료/독립 GET임을 증명하지 않는다.** Task 13의 기존 durable owner가 native control 완료→새 GET request 발행→before와 다른 actual cycle/response→current account 반영의 action 순서와 실제 command/entry/lease/session/issuer identity를 검증한다. ACK/동일 cycle/이전 producer generation은 그 owner가 거절한다. 순수 함수에 새 fake expected-authority DTO를 추가하지 않는다.

## 6. 핵심 typed DTO — 완전한 필드 목록

`Literal`은 exact str/int/bool 타입까지 검사한다. 아래 표의 이름은 제안 공개 이름이며 root 채택 후 plan과 함께 고정한다. DTO의 digest는 caller가 넣는 field가 아니라, 검증된 exact 필드의 닫힌 canonical payload로 계산하는 함수 결과다.

FIXTURE는 pure tests에만 허용되며 actual producer admission에서는 항상 거절한다. 모델의 target environment label도 transport/authenticity 증거는 아니다.

각 digest는 검증된 DTO의 versioned canonical scalar payload에서 계산한다. **계산시각인 LinearSizedEntryV2.assessed_at/LinearAdmissionValuationV2.assessed_at만 각각 sizing/valuation digest에서 제외**한다. audit/codec에는 시각을 보존하되 같은 source snapshot의 재검사는 경제 binding을 유지한다. source 관찰시각/expiry/원본 quote ID 등 나머지는 포함하고 새 now에서 freshness/만료를 재검사한다. Decimal 문자열은 §5A `decimal_text_v2`를 사용해 source sign/coefficient/trailing-zero/scale를 보존하며 ambient capitals에 의존하지 않는다. UTC는 명시 microseconds ISO8601 +00:00, date ISO8601, tuple은 ordered array, product/key/strategy는 명시 객체다. `schema`/`record_type`, canonical ASCII JSON/SHA256은 기존 제안을 유지한다. A02 자체의 source semantic hash 알고리즘은 바꾸지 않는다.

canonical digest payload의 최상위 exact keys는 `schema`, `record_type`, `fields`다. schema=`RISK_V2_CANONICAL_V1`, record_type은 해당 공개 DTO의 정확 이름이다. mark tuple digest만 record_type=`LinearMarkQuoteSetV2`, fields=`{"marks": <canonical tuple array>}`다. dataclass field 이름을 그대로 fields의 key로 쓴다. tuple 최대수 외에도 전체 canonical encoded bytes 65536 상한을 serialization 전에 검사하고 초과하면 `RISK_V2_RESOURCE_LIMIT`이다. 허용 item 수를 줄이거나 원천을 생략해 한도를 맞추지 않는다. derived 결과는 source 256-digit 제한을 다시 적용하지 않되 이 bounded digest/codec 경계를 따른다.

후속 두 module이 공유할 내부 helper signature는 `_mark_values_v2(marks: tuple[LinearMarkQuoteV2, ...], *, required: tuple[InstrumentKey, ...], now: datetime, max_age_seconds: Decimal) -> dict[InstrumentKey, Decimal]`와 `_gross_components_v2(components: tuple[ExposureQuantityV2, ...], *, prices: dict[InstrumentKey, Decimal]) -> Decimal`이다. exact validation 후에만 hash/dict lookup을 수행한다. 반환 mutable dict는 내부 계산용이며 DTO/public API로 내보내지 않는다. derived result를 source representation 제한으로 잘라내지 않고 digest/codec의 별도 bounded bytes 계약으로 보호한다.

```python
    leverage_readback: LinearLeverageReadbackV2 | None) -> LinearEntryAssessmentV2: ...
```

모두 I/O·시계 읽기·native import가 없다. 각 digest API는 먼저 전체 입력을 재검증한다. 각 module은 자신이 소유한 타입의 digest를 제공하고 내부의 닫힌 canonical helper 하나를 공유한다. 타입 이름으로 동적 dispatch하는 공개 범용 serializer는 만들지 않는다.

## 8. 계산의 정확한 순서

1. **Scope/source:** 명시 LINEAR/USDT LinearPerpetual/Trading 및 정확 key/native ID/source rule을 A02 validator로 확인한다. catalog selection/freshness는 producer의 필수 선행 검사다. DEMO account와 PUBLIC_MAINNET market label의 대응은 `source_mapping_revision`과 후속 current issuer가 검증하며 문자열을 바꿔 표시하지 않는다.
2. **고정 adverse 가격으로 quantity:** `distance=limit-stop`(LONG), `stop-limit`(SHORT)는 엄격 양수다. limit/stop은 runtime tick에 맞고 entry limit는 LINEAR min/max order price에 맞는다. stop의 실제 trigger 규칙/자격은 별도 보호 계약이다. `unit_cost=fee+funding+stop_gap`, `unit_loss=distance+unit_cost`, `Q=floor(per_trade_loss/unit_loss/qty_step)*qty_step`. 최소Q 미만/LIMIT maxQ 초과는 거절한다. min/maximum을 맞추려고 Q를 올리거나 내리지 않는다. MARKET maxQ는 별도 원천값으로 보존하되 이 entry 형식에 적용하지 않는다. 유리한 fill이 stop/target을 지나면 attached 보호의 방향/수락도 달라질 수 있으므로 고정 entry bound만으로 모든 fill의 보호 방향을 보장하지 않는다. 실제 fill/보호 검증·실패 대응이 없으면 자동 신규 ENTRY는 계속 차단한다.
3. **Venue notional:** `KnownNotPublished`를 유한 수치로 변환하지 않는다. native max_notional=None을 유지한다. maxPrice×maxQ, riskLimitValue, app cap, 0/Infinity/거대 수를 venue cap으로 넣지 않는다.
4. **Minimum amount:** 위 Q에 결속된, 채택된 product/side/LIMIT ENTRY rule의 fresh 평가를 요구한다. `evaluated_quote_amount == Q*evaluation_price >= instrument.spec.min_quote_amount.value`. rule/source 입력을 입증하지 못하면 `RISK_V2_MINIMUM_RULE_UNVERIFIED`다. mark/limit/LTP 중 편리한 값으로 바꾸지 않는다. close 예외를 ENTRY에 적용하지 않는다.
5. **Fresh mark gross:** 모든 account quantity components와 disjoint held reservation components를 instrument별 fresh mark로 재평가한다. netting하지 않는다. `proposed=Q*selected_mark`, `account_gross=sum(account Q*each mark)`, `reserved_gross=sum(pending Q*each mark)`. `proposed<=max_order`, `account+reserved+proposed<=max_account`. 다른 symbol/외부 활동도 포함하고 mark/source coverage 부족은 거절한다. 과거 notional scalar를 현재 mark로 표시하지 않는다. 이는 검증시점 평가 cap이며 미래 시가 상한이 아니다.
6. **선택적 hard turnover 정책:** HARD이면 BUY만 `Q*ceiling<=max_execution_quote_amount`로 수수료 전 gross 상한을 검사할 수 있다. SELL은 `RISK_V2_SELL_EXECUTION_UPPER_UNAVAILABLE`이다. floor/static maxPrice/공개 price-limit snapshot은 execution upper의 대안이 아니다. NOT_REQUIRED는 이를 요구하지 않는다는 명시 정책 선택이며 fee/margin 문제를 해결하지 않는다.
7. **Tier upper bound:** selected symbol의 account/pending gross quantities와 proposed를 같은 mark로 평가해 U를 만든다. 모든 effective risk value가 U 이하라는 분류/source 근거는 producer 소유다. 전체 `(0,U]`를 table이 덮어야 하며 관련 tier 모두에 대해 `lower=max(user_min,instrument_min,all tier min)`, `upper=min(user_max,instrument_max,all tier max)`다. tier 간 max leverage의 단조성을 가정하지 않고 범위 밖/빈 구간/중복/역전을 거절한다. 실제 tier 하나를 골랐다는 증거가 아니므로 margin/liquidation model이 covered tier 전체를 다루지 못하면 거절한다.

   lower/upper는 연속 교집합이다. §5A의 ZERO_ORIGIN rule로 first/last를 계산하고 선택 leverage의 exact integer membership까지 검사한다. min1.1/max1.4/step.3이면 first=last=1.2이고1.1/1.4는 로컬 rule에서 거절한다. lower1.21/upper1.39/step.3은 연속 구간이 있어도 grid가 비어 실패한다. **Bybit가 이 origin을 보장한다는 주장은 없다.** actual admission은 source/model rule이 이 pin과 일치한다는 별도 검증을 요구한다.
8. **기존 손실 budget:** `loss=Q*unit_loss<=per_trade_loss`, `totalrisk=account.total_risk+reserved.risk_amount+loss`, max_total_risk, daily_loss+totalrisk, drawdown+totalrisk, consecutive losses, position count를 V1과 같은 목적으로 검사한다. account loss day는 now UTC 날짜다. external same-symbol IDs가 비어 있지 않으면 거절한다. 계좌 전체 reconciliation/coverage에는 후속 receipt가 필요하며 빈 tuple 자체가 외부 활동 없음의 증명은 아니다.
9. **Capacity:** `min(margin_allocation,available_margin-held_margin,max_total_margin-account.total_margin-held_margin)`다. 비용만 충당할 수도 없으면 거절한다. leverage를 높여 Q/stop-loss cap을 늘리지 않는다.
10. **Margin/leverage:** qualified E05 model이 이 binding/Q/mode/전체 tier/불리한 entry·mark·fee 조건에 대해 허용 grid의 최소 feasible leverage를 반환한다. 로컬 V2는 exact equality/grid/range/coverage/freshness를 검사한다. V1 `Q*entry/leverage`를 actual IMR 증명으로 쓰지 않고 SDK margin 0.1도 쓰지 않는다. `required_reservation=max(initial_margin_quote+planned_cost_allowance,venue_required_total_reserve_quote)`이며 capacity 이하여야 한다. 같은 fee를 두 번 더하지 않고 V1 cost allowance를 margin budget에서 없애지 않는다. 최소 leverage 증명/실제 model 식은 E05 외부 의존이며 pure DTO 검증의 성과가 아니다.
11. **Liquidation/readback:** binding/margin digest와 §5B의 supplied causal order를 검사하고 buffer predicate는 exact 곱셈 비교다. actual control/독립 GET/current generation의 정당성은 Task13 existing runtime owner가 검증한다. 순수 Task6은 잘 구성된 wrong control key/ACK처럼 위장한 source/old generation을 구별할 기대 identity가 없으므로 그 자격을 입증하거나 거절했다고 주장하지 않는다. 새 digest 없는 V1 evidence를 재사용하지 않는다.
12. **PLAN/SUBMIT:** prepare는 항상 무권한이다. PLAN은 missing margin/liquidation/readback을 고정 blocker로 표시하고, 값이 모두 있어도 `RISK_V2_PLANNING_ONLY`다. SUBMIT은 하나라도 누락/오래됨/불일치면 예외다. 모두 맞아도 계산 출력일 뿐이며 후속 current-issuer admission이 별도로 필요하다. 명시 now로 내부 prepare를 재계산하고 caller가 만든 preparation을 신뢰하지 않는다.

PLAN에서도 margin이 없는데 liquidation/readback 값만 있는 조합은 `RISK_V2_INPUT_INVALID`다. margin 없이 해당 leverage/margin digest를 검증할 수 없으므로 supplied evidence를 무시하지 않는다. margin만 존재하고 liquidation/readback이 없는 PLAN은 두 missing blocker를 반환한다. SUBMIT은 모든 supplied 논리 타입/결속 검사를 수행하며 누락은 명시 blocker 예외다. pure 성공은 actual model/GET/issuer qualification을 뜻하지 않는다.

## 10. 예약·native·persistence 후속 계약

**Fresh mark 예약:** 첫 pure slice는 journal을 건드리지 않는다. 현 scalar reservation을 mark valuation으로 이름만 바꾸는 이행은 금지한다. 후속 journal은 §16의 local held quantities/revision/immutable command/owner epoch만 CAS한다. bound account/policy/mark 값으로 exact capacity를 계산할 수 있지만 venue account/catalog/policy의 currentness를 DB transaction으로 CAS했다고 말하지 않는다. 그 currentness는 같은 §16의 runtime publication fence/actual producer가 소유한다. V1 scalar 예약이 남으면 관리/복원을 유지하고 V2 새 ENTRY는 명시 reconciliation blocker다. 기존 자산의 합법 감축 EXIT는 별도 ownership/보호/대사 경계를 유지한다.

**Native envelope:** 후속 새 version request는 `FixedLimitEnvelopeV2`에 exact client ID/position ID/owned role·generation/attached protection을 결속하고 factory.limit에 `time_in_force=TimeInForce.IOC`를 명시한다. factory protocol/lazy bindings/fake·pinned tests를 함께 바꾼다. built order에서 ID/native instrument/side/Q/limit price/LIMIT/IOC/reduce_only=False/base quantity/post_only=False 등 실제 native 속성을 재대조한다. allowed params는 현 position_idx=0과 검증된 attached 보호뿐이며 BBO/price override/slippage 임의 dict는 받지 않는다. SPOT은 별도 product request에서 is_leverage=False/is_quote_quantity=False/reduce_only=False 및 cash/inventory를 검사하고 LINEAR idx 계약을 그대로 복제하지 않는다.

**Versioned persistence:** 새 schema에 compact InstrumentPinV2와 policy/envelope/sizing/binding/model revisions·digests, product/TIF/qty/price/expiry를 명시 저장한다. raw catalog/다량 source records는 기존 또는 후속 bounded source store의 digest로 참조하고 유실되면 신규 ENTRY를 멈춘다. raw를 생략한 compact pin만으로 재실행하지 않는다. 기존 codec registry/schema 원형 읽기를 보존하고 새 decoder는 구 writer가 열지 못하는 version으로 한다. restore는 observe/manage이며 current producer admission을 복원하지 않는다. 이전 MARKET intent를 LIMIT/IOC로 바꾸거나 재송신하지 않는다. partial/zero fill도 terminal execution/history 대사 전 예약을 보유하고 UNKNOWN은 재전송하지 않는다. 새 시도는 새 plan/reservation/intent다.

**EXIT:** 신규 ENTRY cap 초과 때문에 적법한 보유 감축을 영구 중단하지 않는다. LINEAR는 current exclusive position 이하 reduce_only와 기존 writer/보호/대사, SPOT은 소유 lot/available base와 base fee 예약을 요구하는 별도 exit 계약으로 판정한다. role 문자열만 있는 가짜 EXIT나 exposure 증가는 거절한다. ENTRY 고정가격 채택으로 기존 EXIT/STOP gap 의미를 바꾸지 않으며 주문형식/분할/실패시 보호는 root가 독립적으로 채택·검증한다.

## 11. SPOT의 독립적인 최소 경계

SPOT에 LINEAR mark/tier/margin/leverage/liquidation/funding의 가짜 값을 넣지 않는다. A02 `SpotInstrumentSpec`의 base_precision/quote_precision/min_quote_amount/max_limit_quantity와 KnownNotPublished를 사용한다. cash BUY는 `Q*buy_ceiling+verified quote fee upper`, SELL은 `Q+verified base fee upper`를 같은 account 전체 cash/base 예약과 각각 대조한다. SELL floor는 proceeds 상한이 아니다. fresh account-wide debt coverage가 완전하고 각 asset의 차입/이자/부채=0으로 설명되지 않으면 cash entry를 허용하지 않는다. is_leverage=False만으로 무차입을 증명하지 않는다.

이 A07 준비에서 새 SPOT risk policy 전체를 발명하지 않는다. 다음 값 계산만 후속 독립 `spot_risk.py`에 정의할 수 있으며, 전체 trade risk/stop/TP/owned lot/history/receipt 완성은 아니다.

```python
@dataclass(frozen=True)
class SpotCashRequirementV2:
    quote_debit: Decimal
    remaining_quote: Decimal

@dataclass(frozen=True)
class SpotBaseRequirementV2:
    base_debit: Decimal
    remaining_owned_base: Decimal

def check_spot_cash_buy_v2(*, quantity: Decimal, buy_ceiling: Decimal,
    fee_quote_upper: Decimal, available_quote: Decimal, held_quote: Decimal,
    max_order_quote_debit: Decimal, max_total_quote_commitment: Decimal) -> SpotCashRequirementV2: ...
def check_spot_owned_sell_v2(*, quantity: Decimal, owned_available_base: Decimal,
    held_base: Decimal, fee_base_upper: Decimal) -> SpotBaseRequirementV2: ...
```

raw balance를 소유 lot로 보지 않는다. 제3화폐 fee/unknown fee/base fee/외부 asset/차입을 숨기지 않으며 미지원이면 멈춘다. 기존 LINEAR history의 SPOT 활동 거절을 삭제하지 않는다. SPOT entry 보호 미자격은 `SPOT_PROTECTION_NOT_QUALIFIED`를 유지한다. SPOT full assessor/ledger/producer의 세부 schema를 E16 별도 spec에서 확정하기 전 이 산술을 runtime에 연결하지 않는다.

## 16. I1 — local journal CAS와 current publication fence

**Journal의 정확 책임:** 새 V2 metadata row에 local capacity revision(exact nonnegative int)과 current owner_epoch를 저장한다. revision은 held quantity/risk/margin/count 집합·capacity에 영향을 주는 command identity/예약 등록·증액·감액·확정해제·owner epoch 전환 때 증가한다. 단순 PENDING→SENDING/UNKNOWN/ACK 등 동일 nonterminal 예약을 유지하는 상태 전이만으로 capacity revision을 바꾸지 않는다. command state는 별도 SQL 조건과 immutable identity 비교로 CAS한다. 이 정의를 전체 외부 상태 revision이라고 표현하지 않는다.

held_quantity_sha256는 모든 미확정 예약의 정렬된 `(command_key,client_order_id,payload_hash,version,instrument,base_quantity,envelope_sha256,risk_amount,margin_amount,position_count)`를 덮는다. nonterminal 상태 간 변화는 집합/quantity가 같으면 hash가 같다. terminal 확정해제로 집합이 바뀌면 revision/hash 모두 바뀐다. 같은 captured reservation snapshot을 source/model 계산부터 claim 직후 마지막 guard까지 유지하며, 현재 DB의 revision/hash/epoch와 대조한다. 새 audit now만으로 snapshot을 재발급하지 않는다. 실제 snapshot을 새로 읽어 receipt 시각/경제 metadata가 달라졌으면 모델 binding도 새로 계산한다.

`register_entry_v2`의 BEGIN IMMEDIATE 안에서 (1) actual stored owner_epoch, (2) capacity revision, (3) actual held quantity hash, (4) 같은 key의 immutable command identity를 expected local pins와 비교한다. given policy/account/mark로 exact capacity를 다시 계산하고 등록/예약/revision 증가를 함께 commit한다. 같은 command의 정확 idempotent 등록은 중복 capacity를 만들지 않으며 stale local pins를 조용히 무시하지 않는다. `claim_entry_v2`는 같은 local pins와 actual command identity 및 `state=PENDING`을 조건으로 durable SENDING claim을 취득한다. 이미 UNKNOWN/ACK/SENDING이면 재전송 자격을 만들지 않는다. epoch/revision/held hash/key 충돌은 고정 local conflict다.

local identity helper는 `entry_command_identity_sha256_v2(account_scope: ProtectionScope, command_key: str, intent: DurableEntryIntentV2, reservation: ReservationV2) -> str`다. canonical domain `LocalEntryCommandIdentityV2`의 exact fields는 account_id/environment/command_key/kind=`ENTRY`/`intent_sha256`(exact encode_entry_intent_v2 UTF-8 bytes hash)/`reservation`(version/instrument/envelope hash/Q/risk/margin)다. 실제 client_order_id는 기존 journal의 같은 scope/key deterministic generator와 별도로 대조한다. expected hash와 현재 저장된 payload/예약에서 재구성한 hash가 같아야 한다. 외부 source currentness나 expected control 권한을 발급하는 DTO가 아니다.

추가 local owner 연결 API는 `bind_owner_epoch_v2(owner_epoch: str, *, expected_previous_owner_epoch: str | None, expected_journal_revision: int) -> int`다. 기존 runtime의 실제 account lease를 가진 owner가 §아래 fence 안에서만 호출하고 이전 epoch/revision을 CAS한다. 문자열을 안다는 이유만으로 실제 lease가 생기지 않는다. decoder/import가 이 method를 호출하지 않는다.

**Runtime/producer의 정확 책임:** 실제 worker instance와 기존 lease/session/binding/native channel/current risk producer의 object identity를 캡처한다. 그 owner가 같은 account/environment의 risk-affecting policy/catalog/source/model publication을 **하나의 기존 owner-loop admission fence**로 직렬화한다. 다른 thread/process의 정책 쓰기도 active owner의 기존 command queue로 marshal하거나 admission을 차단한다. 직접 DB writer와 독립 catalog hot swap을 남긴 상태에서는 원자 currentness를 주장할 수 없다. fence 도중 publisher의 재진입 갱신은 허용하지 않고 queued publication으로 미룬다. 새 범용 authority framework나 금융 bool은 없다.

fence에서 캡처/재대조할 exact pins는 §15 producer signature의 모든 값이다: actual policy publication revision+policy hash, catalog generation+semantic revision, source generation/mapping, model generation/requirements, full risk-domain hash, account snapshot hash, mark set hash, reservation snapshot ID/local revision/held hash/owner epoch, immutable plan/envelope/binding/command identity. 값 비교 외에 actual owner/session/binding/channel/producer 객체가 같은지도 기존 guard로 검사한다. 필드가 같은 복사 객체는 current issuer가 아니다.

최종 dispatch 순서는 **fence 진입 → 실제 current issuer/정책·source/model/current account·mark·held coverage·freshness/실제 GET owner 검사 → exact risk와 충분한 기존 reservation 확인 → local claim CAS → 같은 captured pins와 actual owner 마지막 guard → 같은 native bridge 동기 handoff → fence 해제**다. 이 구간에는 await/thread handoff가 없다. network/source 수집과 leverage effect/독립 GET은 앞서 await하고 fence 진입 후 전후 actual owner/currentness를 다시 확인한다. 실제 venue account는 계속 변할 수 있으므로 보장하는 것은 local publication의 직렬화와 유효한 bound receipt/currentness이지 외부 거래소 상태의 CAS가 아니다.

Task11의 시험은 local DB revision/held/command/epoch 경쟁만 소유한다. policy/catalog/source/model publication/stop/lease/session 교체와 실제 control/GET mapping 경쟁 시험은 Task13 owner가 소유한다. 새 margin 요구가 실제 held margin reservation보다 크면 자동 축소/해제·임의 덮어쓰기 없이 신규 ENTRY를 막고 별도의 명시 재예약/새 intent 절차를 요구한다.

## 17. I2 — 신규 selection과 전체 held LINEAR risk domain

`LINEAR_MARK_GROSS_AT_ADMISSION_V1`의 account-wide는 **지원 LINEAR 평가 domain 전체의 gross**다. 다른 상품의 현금/base/debt까지 평가 완료했다는 뜻이 아니다. E04/A08/E16이 실제 계좌 전체 completeness/공유 자본을 별도로 검증해야 하며 미지원 경제활동을 필터로 숨기지 않는다.

producer는 먼저 실제 allowed/selected로 A02 `require_catalog_selection`을 호출해 신규 진입 허용을 검증한다. 그 selected 반환만을 전체 위험 universe로 사용하지 않는다. `risk_keys = proposed_key ∪ account.components.keys ∪ reservations.components.keys`를 만들고 같은 검증된 current catalog의 observations에서 모든 key를 risk valuation 목적으로 resolve한다. allowed/selected=(XAA)이고 held YBB가 있어도 YBB를 새로운 후보로 허용하지 않으며, YBB mark/instrument/tier/margin/risk/count는 계속 포함한다.

Task13에서만 연결할 후속 coverage 값 타입은 다음과 같다. 값 생성은 자격이 아니며 실제 producer는 source registry/모델 입력을 대조해야 한다.

| 타입 | 완전한 필드 |
|---|---|
| `LinearRiskDomainMemberV2` | `instrument_pin: InstrumentPinV2`, `mark: LinearMarkQuoteV2`, `tiers: LinearTierSnapshotV2`, `account_component_ids: tuple[str, ...]`, `reservation_component_ids: tuple[str, ...]`, `account_risk_quote: Decimal`, `account_margin_quote: Decimal`, `account_position_count: int`, `reserved_risk_quote: Decimal`, `reserved_margin_quote: Decimal`, `reserved_position_count: int`, `account_margin_reference: RiskObservationRefV2`, `account_risk_reference: RiskComputationRefV2`. 금액/개수는 nonnegative이며 ID 집합이 해당 instrument의 실제 component 집합과 정확히 같아야 한다. |
| `LinearRiskDomainCoverageV2` | `account_scope: ProtectionScope`, `catalog_revision: str`, `selected_entry_key: InstrumentKey`, `coverage_revision: str`, `source_generation: str`, `members: tuple[LinearRiskDomainMemberV2, ...]`, `account_snapshot_sha256: str`, `reservation_snapshot_sha256: str`, `mark_set_sha256: str`, `source_record_sha256s: tuple[str, ...]`. members는 key 순으로 1..100, risk_keys와 정확 일치한다. |

후속 순수 builder signature는 `build_linear_risk_domain_coverage_v2(*, policy: LinearRiskPolicyV2, catalog: InstrumentCatalog, catalog_revision: str, coverage_revision: str, source_generation: str, account: LinearAccountRiskSnapshotV2, reservations: LinearReservationSnapshotV2, marks: tuple[LinearMarkQuoteV2, ...], members: tuple[LinearRiskDomainMemberV2, ...], now: datetime) -> LinearRiskDomainCoverageV2`와 `risk_domain_sha256_v2(value: LinearRiskDomainCoverageV2) -> str`다. selected_entry_key는 policy.scope.instrument에서 얻는다. policy의 quote/evidence age로 member mark/tier/readback/computation freshness를 검사한다. current actual producer가 source objects를 공급하며 hash만으로 자격을 생성하지 않는다.

builder는 catalog의 공개 static integrity와 expiry/future/관찰 validator를 재검사하고, 정확 모든 risk key의 catalog pin·mark·tier source를 대조한다. 각 held symbol의 instantaneous gross U가 그 tier table 범위에 덮이는지 검사한다. proposed X의 user leverage 범위를 held Y에 소급 적용하거나 Y leverage를 자동 변경하지 않는다. Y의 실제 applied leverage/margin은 actual E05 model/source/readback 계약이 소유한다. 전체 member의 account risk/margin/count 합계는 account header totals와, reserved 합계는 reservation header totals와 exact 일치해야 한다. 현재 margin/risk source의 내용·분류·과거 fill 반영/실제 count는 issuer가 원문으로 입증한다. source receipt/model computation 시각 모두 §5B margin 완료 하한에 포함한다.

preflight가 확인한 공식 mark/tier의 긍정 근거를 유지한다. 같은 instant mark에서 nonnegative 전체 gross 합은 방향별 합의 max 이상이며 Bybit의 USDT/USDC mark 평가/effective risk 설명과 양립하는 보수적 U다. 정확한 source 분류/coverage가 전제이고 actual tier 하나/미래 mark 상한을 증명하지 않는다. 이번 R2 작업은 공식 source를 새로 조회하지 않았다. [preflight가 확인한 Bybit Risk Limit](https://www.bybit.com/en/help-center/article/Risk-Limit-Perpetual-and-Expiry-Contracts).

actual producer는 이 coverage 객체/원문들을 private receipt registry에 유지하고 그 hash를 LinearRiskInputs/Binding의 risk_domain_sha256에 결속한다. model은 모든 members를 입력으로 소비하고 실제 source-model mode gate를 통과해야 한다. pure core는 이 hash를 syntax/binding 수준에서만 검사한다. Task13은 issuer 내부 actual coverage가 없거나 일부 key/원문/시각이 미해결이면 거절한다.

필수 반례는 declared=(XAA,YBB), allowed/selected=(XAA), account held YBB/pending XAA/proposed XAA다. YBB mark/tier/margin/count를 빼거나 selection 변경만으로 YBB component를 지우면 신규 ENTRY는 실패한다. held가 current declared catalog 밖/미지원 product/source면 새 ENTRY를 막고 그 항목을 삭제/샘플링/가짜 LINEAR mark로 치환하지 않는다. 적법한 기존 소유 감축 EXIT는 별도 current ownership/모드/보호/대사 계약으로 유지한다.

## 18. root 비용과 후보 동결 범위

추가 구현 비용은 작은 exact math leaf module/test, grid/DAG/digest/derived-validator 수정, 기존 runtime 소유의 publication fence와 local CAS pins, 실제 full-held source coverage다. 기존 V1 계산기 재작성/범용 authority framework/새 provider client는 필요 없다. 실제 E05-M1/M2/M3는 반드시 구현·source/readback 수락해야 하는 별도 후속 산출물이며 이 후보가 실제 margin/fee/liq 식·자본·수익·운영 TTL/승인 issuer를 발명하지 않는다. local ZERO_ORIGIN rule이 실제 source/model과 맞지 않으면 금융 admission은 unsupported이며 규칙 revision을 명시적으로 다시 설계한다.

R2 문서 작업의 완료는 후보 동결까지만이다. **fresh independent preflight 전 채택/구현 완료/PASS로 보고하지 않는다.** 원본 두 문서는 그대로 보존하며 이 후보의 범위 밖 source·제품·테스트·Git/금융 작업은 하지 않았다.
