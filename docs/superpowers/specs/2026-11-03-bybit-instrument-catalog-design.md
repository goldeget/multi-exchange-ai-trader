## Definitions and immutable observation

All DTOs are frozen dataclasses with exact runtime field/container types, validated constructors. Public boundaries revalidate exact objects against forged/missing fields; frozen does not establish provenance.

- `DecimalField(raw: str, value: Decimal, scale: int)`: raw matches ASCII `(?:0|[1-9][0-9]*)(?:\.[0-9]+)?`, at most64 digits in total and32 fractional digits, at most65 chars. Value exact Decimal finite and strictly positive; `value.as_tuple()` equals exact `Decimal(raw).as_tuple()` and scale exact int equals fractional digit count. No normalize/rounding/ambient context dependence. Raw zero, exponent, sign, leading-zero aliases, whitespace, float/bool/int/Decimal-as-source are rejected. This positive source-field type is not a general fee/price computation type.
- `CatalogSource(source_id: str, source_environment: SourceEnvironment, endpoint: str, received_at: datetime)`: exact values as above. Time accepts exact `datetime` with exact standard `datetime.timezone` tzinfo and non-null offset, normalized to UTC. Reject datetime subclasses, naive/custom/ZoneInfo tzinfo, rather than invoke arbitrary timezone hooks. This is a local supported input envelope, not a venue requirement.
- `KnownNotPublished(field: Literal["max_quote_amount"], source_rule_revision: str)`: only the two fixed source-rule revisions. Means that this supported source rule publishes no max order quote amount field; not infinite venue/account permission and not permission to replace missing required data.
- `LinearInstrumentSpec(base_coin, quote_coin, settle_coin, contract_type, status, source_price_scale, price_tick, min_price, max_price, quantity_step, min_quantity, max_limit_quantity, max_market_quantity, min_quote_amount, min_leverage, max_leverage, leverage_step, max_quote_amount, is_pre_listing)`. Coin strings exact ASCII `[A-Z0-9]{1,32}`, quote/settle exact `USDT`, contract exact `LinearPerpetual`, status exact `Trading`, source_price_scale exact int0..32, last field exact bool False. All numeric fields except source_price_scale are DecimalField; max_quote_amount is KnownNotPublished with LINEAR rule. Same-unit constraints: min_price<=max_price, min_quantity<=each quantity cap, quantity_step<=each cap, min_leverage<=max_leverage and leverage_step<=max_leverage. Do not assume tick.scale==source_price_scale or ordering between the two caps; no undocumented grid-divisibility requirement.
- `SpotInstrumentSpec(base_coin, quote_coin, status, price_tick, base_precision, quote_precision, min_quote_amount, max_limit_quantity, max_market_quantity, max_quote_amount)`: exact base coin above, quote USDT, status Trading; six numeric fields are DecimalField. base_precision<=each quantity cap. No synthesized min quantity, settle, leverage or min/max price. max_quote_amount carries SPOT rule.
- `InstrumentObservation(key: InstrumentKey, native_instrument_id: str, parser_revision: str, source_rule_revision: str, specification_revision: str, source: CatalogSource, response_time: datetime, raw_row_canonical: bytes, raw_row_sha256: str, spec: LinearInstrumentSpec | SpotInstrumentSpec)`. Raw bytes are `repr=False`; exact bounded canonical row only. Digests/revisions are lowercase64-hex SHA256. Exact key is revalidated with existing helper; product/spec/rule/native ID agree. Observation constructor validates types/nested values/canonical raw/hash and parsed supported fields against every derived value using the same parser logic. No recursive observation construction loop. Export `validate_instrument_observation(observation: InstrumentObservation) -> None` for downstream revalidation; it must not trust constructor history or untrusted equality hooks.

## Single-symbol parser

`parse_bybit_instrument_response(body: object, *, expected: InstrumentKey, source: CatalogSource) -> InstrumentObservation`.

Validate exact expected/source first, then bounded JSON before serialization/hash/known Decimal conversion. Body must be exact dict with exact int retCode0 (bool rejected); nonzero exact code gives PROVIDER_REJECTED. Exact dict result, category equal shared helper, exact list of exactly one exact dict row, exact expected symbol, positive exact int time in1..253402300799999 milliseconds. Optional nextPageCursor must be exact empty str. Cursor absence is accepted; nonempty cursor rejected, never pretend a whole venue listing was fetched. Parse server time by UTC epoch plus integer timedelta(milliseconds=time), never float timestamp. Missing/malformed envelope gives RESPONSE_INVALID; category/symbol mismatch gives SCOPE_MISMATCH.

Row must have status Trading, explicit baseCoin and quoteCoin USDT. LINEAR requires settleCoin USDT, contractType LinearPerpetual, source priceScale as specified below, isPreListing exact bool False; priceFilter minPrice/maxPrice/tickSize; lotSizeFilter qtyStep/minOrderQty/maxOrderQty/maxMktOrderQty/minNotionalValue; leverageFilter minLeverage/maxLeverage/leverageStep. **Bybit priceScale is a string on the documented wire response**: accept only exact ASCII decimal integer string0..32 with no sign/leading-zero alias, store source_price_scale as int after bounded parse. An int/bool priceScale in a source response is invalid. (The stored DTO field remains exact int.)

SPOT requires priceFilter tickSize and lotSizeFilter basePrecision/quotePrecision/minOrderAmt/maxLimitOrderQty/maxMarketOrderQty. Deprecated minOrderQty/maxOrderQty/maxOrderAmt may remain only in raw hash, never fallback or authoritative cap. Both order-kind caps are mandatory in this first strict source revision; absent/null/zero is FILTER_INVALID. LINEAR preListingInfo may be absent or None only; non-null is INSTRUMENT_UNSUPPORTED even with isPreListing False. Only regular Limit/Market source rules are represented; this does not support PostOnly/RPI/conditional/TP/SL/auction/special asset rules or dynamic price limits. Unknown fields may be retained bounded in raw row, without claiming all venue constraints were interpreted. Unsupported known product/status/quote/settle/contract/prelisting gives INSTRUMENT_UNSUPPORTED; malformed required fields/decimal/range gives FILTER_INVALID.

Bounded JSON accepts exact dict/list/str/int/bool/None only, never floats/subclasses/other objects. Mapping keys exact str. All keys/string values<=128 Unicode codepoints and contain no surrogate codepoints U+D800..U+DFFF; canonical JSON uses ensure_ascii=True, sort_keys=True, separators=(",", ":"), allow_nan=False, encoded ASCII bytes. Preserve other Unicode exactly, no normalization. Maximum depth8(root=1), total nodes4096(count each container, mapping key and value), each container<=128 entries, ints absolute<=2**63-1. Reject cycles using current-path identities. Prewalk counts exact canonical encoded bytes incrementally including escaped strings, punctuation and commas, stopping above65536 before aggregate serialization. Full envelope and row each obey64KiB. No input hooks/hash/repr/format before exact-type checks. These are local resource bounds, not venue maxima. Already-decoded dict input cannot reveal duplicate wire keys a prior decoder discarded; later HTTP producer must reject duplicates before creating this body value.

On revalidating raw observation bytes: exact bytes/nonempty/size<=65536 precedes json.loads; bounded parse_int text-length/range, reject float/constants, duplicate-key rejection, expected decoder/recursion/overflow errors become fixed OBSERVATION_INVALID. Validate the decoded tree and canonical byte equality, then reparse supported fields and compare derived values/digests; noncanonical JSON or a forged hash/spec/source/key/revision is rejected as applicable. Observation constructor also requires response_time<=source.received_at, giving TIME_INVALID otherwise. Observation raw row does not contain envelope category/time; the response_time is validated logically as an exact supported UTC time but remains caller-supplied. A replacement timestamp that remains logically valid is not independently detectable from row bytes. Neither original envelope receipt integrity nor authenticity is claimed.

## Semantic revisions

Raw row hash is SHA256(canonical row bytes), not HTTP raw bytes or signature. Supported spec revision hashes canonical payload with keys `key` (venue/product/symbol), `native_instrument_id`, `parser_revision`, `source_rule_revision`, `spec`. Spec payload uses exact dataclass field names; DecimalField encoded as `{raw,value,scale}` with value equal raw (fixed source spelling), KnownNotPublished as its two fields; other fields exact primitives. Thus tick0.10 vs0.1 changes source precision/revision; no supported numeric aliases are silently normalized. Time/source_id/extra raw fields excluded. Raw additional-field changes can change raw hash without supported semantic revision. V1 accepts exactly one fixed rule per product: tests reject wrong/unknown rules and pin payload membership, rather than inventing a second accepted rule. A future explicitly supported rule must have a different semantic revision. Export internal canonical helpers only as needed between these two modules; no duplicate hash algorithm.

Task1 supplies shared internal `_canonical_json_bytes(value: object) -> bytes`, `_key_payload(key: InstrumentKey) -> dict[str, str]` and `_utc_datetime(value: datetime) -> datetime` for Task2. The first applies the same bounded canonical JSON contract; key helper revalidates with the existing product helper; datetime helper implements the exact standard-fixed-offset contract. Do not duplicate canonical JSON, key or time algorithms in Task2. These helpers remain internal, pure and non-authoritative.

## Catalog and selection

`InstrumentCatalog(schema_version: int, revision: str, declared_universe: tuple[InstrumentKey,...], observations: tuple[InstrumentObservation,...], max_age: timedelta, expires_at: datetime)`. Computed read-only property `complete_for_declared_universe` revalidates static catalog integrity on every access, returning True only if valid, otherwise raising fixed CatalogRejected; it reads no clock and does not prove freshness. No caller-provided completeness/qualification bool. Constructor rejects bad types, noncanonical order, duplicate/missing/extra keys, schema/revision/expiry mismatch and source disagreement, independently of wall clock. All keys/observations sorted by `(venue, product, symbol)`;1..100 each. Products may be mixed, same-symbol products remain distinct. Every observation must have identical source_id/environment/endpoint (received_at may vary). max_age exact positive timedelta, expiry arithmetic overflow rejected.

`build_instrument_catalog(observations: tuple[InstrumentObservation,...], *, declared_universe: tuple[InstrumentKey,...], now: datetime, max_age: timedelta) -> InstrumentCatalog`: exact tuples, no duplicates, nonempty1..100; revalidate every observation, one source domain/id, exact set coverage before canonical sorting. All response_time<=received_at<=now. Each time must be strictly newer than now-max_age. expires_at is min(all response_time/received_at)+max_age; now>=expiry is EXPIRED. Reject future/inverted times TIME_INVALID and catch overflow. No default TTL or clock read.

Catalog revision hashes canonical payload with keys `schema_version`, `parser_revision`, `source_rule_revisions` (sorted unique strings), `source_environment`, `endpoint`, `declared_universe` (canonical key objects), `specifications` (list in canonical key order; each entry EXACTLY `{"key": {"venue": ..., "product": ..., "symbol": ...}, "specification_revision": "<64 lowercase hex>"}`), `max_age_microseconds` (exact integer timedelta components). Exclude all observation times, raw hashes, source_id; rebuild with only collection-time/id/raw-extra changes retains semantic revision. source_id consistency is still revalidated; excluding it is not authentication. Catalog integrity does not establish a current catalog issuer or generation.

`require_catalog_selection(catalog: InstrumentCatalog, *, allowed: tuple[InstrumentKey,...], selected: tuple[InstrumentKey,...], expected_product: TradingProduct, expected_source_environment: SourceEnvironment, expected_revision: str, now: datetime) -> tuple[InstrumentObservation,...]`: revalidate entire catalog integrity/freshness, then exact expected arguments; revision equality, source environment, exact nonempty duplicate-free tuples with selected subset allowed subset declared. Every allowed and selected key has expected_product; unrelated products may remain declared in the catalog but remain fully integrity/freshness checked. Unknown allowed is rejected, never filtered. Return selected observations in selected input order. No partial publication. A copied old catalog with matching old expected_revision can pass static validation until expiry; trusted current producer/generation and PLAN→SUBMIT recheck are later mandatory admission gates.
