## Versioned educational contract PAPER-v1

These are builder-selected simulation assumptions, not exchange specifications or user-specified leverage guarantees. Display them in the PAPER UI. All instruments and quotes are independent synthetic local scenarios: BTC-PAPER and ETH-PAPER, native IDs BTC-USDT-PERP.PAPER/ETH-USDT-PERP.PAPER. Never map Binance spot into futures marks. New scenario starts once at10000 virtualUSDT with explicitly labeled seed marks60000.0/3000.00. One-way netting, at most one entry per instrument until flat; no adding/reversing an open position. Isolated margin is an application risk allocation over native margin-account cash/positions, not a claim that native/exchange cross-margin locks are isolated.

Leverage strict integer1..20. BTC tick0.1/quantity step0.001/min0.001/max10; ETH tick0.01/quantity step0.01/min0.01/max100. Positive decimal strings only; reject JSON floats, booleans, exponent/NaN/Inf, precision or tick/lot violations. Mark bound1..1000000; entry notional cap100000. Fee0.0004 per native fill, adverse1 native price tick for market/conditional-market fills, deterministic native FillModel probability1/seed42, full fills from synthetic quote depth1000 units. Margin reservation is entry fill notional/leverage rounded up to8 USDT decimals; partial exit releases the proportional remaining allocation. Native fees/Money are authoritative; store all ledger numerics as decimal strings. Quantization and any native rounding discrepancy must be explicit/reconciled, never erase a loss.

Supported: market long/short entry, reduce-only partial/full market exit, set/replace/cancel SL and/or TP, native STOP_MARKET and MARKET_IF_TOUCHED with OCO when both set. Thresholds must be on the appropriate side of the current mark. Native quote ticks have bid=ask=local mark, so conditional triggers use that local mark; native slippage produces adverse executions. Tick events, not OHLC ordering: there is no optimistic intra-candle path. No limit entry, pending discretionary order edit, expiry, arbitrary order type, simulated queue/volume partial fill or live funding claim. Partial position close is not a claim of volume-limited partial order fills.

Liquidation: educational approximate MMR0.005. On a tick, if allocated isolated margin + native unrealizedPnL <= current notional*(MMR+takerFee), cancel remaining protection and submit native reduce-only market exit. Native conditional exits may already have closed the position; check native cache again to prevent another exit. No claim of exchange liquidation parity. Gaps execute at the new local quote plus adverse slippage, not the trigger. Negative wallet/equity remains debt, blocks entry, and is never reset/clamped away. Available=max(wallet-reserved,0), deficit=max(reserved-wallet,0), so available+reserved-deficit=wallet; equity=wallet+native unrealizedPnL.

## Deterministic events and storage

Tick source exactly LOCAL_SCENARIO_V1; global scenario sequence strictly increases, UTC timestamp strictly increases across ticks. Reject future ticks and >120s-old ticks at ingestion, duplicate/reversed sequence/time, invalid source/value. Recorded receipt time governs historical validation on replay; replay does not reject previously valid historical data merely because wall time advanced. Entry requires a fresh mark. Native execution uses a separate disclosed deterministic replay clock, not a fabricated exchange timestamp.

SQLite stores schema/version, scenarios, canonical command payloads/results and append-only events/fills/settlements. BEGIN IMMEDIATE and process locking serialize commands; commands include a scenario-scoped idempotency key. Same key+same payload returns the original committed result even after restart; same key+different payload conflicts. Initial funding occurs only on new scenario. No delete/reset endpoint; a new scenario gets a new ID. DB/WAL/SHM/state files are gitignored and never committed. Hash-chain and native replay reconcile stored snapshots/fills; unknown schema, truncated/corrupt data or reconciliation mismatch fail closed. No tamper-proof or external authentication claim.

Rebuild the native cache by deterministic replay for every transaction/restart; bounded scenarios (initially max500 accepted events) make this simple and reviewable. This is intentionally not a high-throughput service. Native event UUIDs are not reconciliation identities; deterministic client-order IDs, decimal fill/fee results and application sequence are. Cash from native account, positions/unrealized from native cache, audit valuations from actual native fills. Application risk/ledger checks are not an alternative fill engine. Preserve prior committed DB state if candidate replay or SQL fails. Simulated command/tick execution never calls an external transport.
