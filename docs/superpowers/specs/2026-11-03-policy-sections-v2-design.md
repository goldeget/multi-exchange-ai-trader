## Intent, baseline and approach

Extend the existing same-book schema2 draft, currently closed to three null sections, with explicit product/account/universe/mode, exact static strategy metadata and partial LINEAR financial inputs. Return a nonauthoritative LinearRiskPolicyV2 only for a complete compatible supplied RiskScopeV2. Saving remains STOPPED/False/False and ENTRY remains blocked even when missing_fields is empty.
Recommended: retain storage/read schema2 and the four policy keys; scope and strategy use section_version=1 while risk_v2 uses section_version=2. Add a capable-write request marker policy_sections_version=2. Old null-only readers/writers already refuse non-null stored sections; the marker also protects an old browser talking to the NEW server from erasing initialized sections.
Alternative schema3 would force another explicit migration and a new recovery/storage union despite unchanged table layout. A monotonic section-presence rule would block a LINEAR-to-SPOT switch because SPOT requires risk_v2=null; the explicit capable-write union below permits intentional switching under CAS. Embedding a new current catalog publisher would widen authority/source ownership; do not introduce one.
Use runtime_policy.py for storage/CAS/projection, settings_api.py for the existing routes, and a new execution/policy_sections.py for this substantial closed wire codec and static cross-section validation. Do not refactor V1 validation or generalize execution/codec.py.

## Exact wire notation and shared validation

Every listed key is mandatory; unknown/missing keys, duplicate JSON keys at any depth, bool-as-int, floats, nonfinite numbers and wrong container/scalar types fail before mutation. JSON arrays decode to exact tuples for typed constructors; production payloads never import arbitrary classes.
`D` = existing draft decimal-string grammar `(?:0|[1-9][0-9]{0,15})(?:\.[0-9]{1,8})?`; preserve its lexical spelling in storage/read/UI. Require positive value except the three explicitly nonnegative fields below. This deliberately retains the current operator-input envelope, narrower than Risk V2 mathematical/source bounds; extending precision needs a new reviewed wire decision.
`I` = exact int 1..1_000_000. `ID` = current strategy identifier grammar `[A-Za-z0-9][A-Za-z0-9_.:/-]{0,95}`. `H` = 64 lower-case hex; `CR` = `sha256:` plus H. Strategy revision cannot casefold to `latest`. All list/set-like collections max100, no duplicate members; reject rather than silently deduplicate or filter.
`Key` = exact `{venue,product,symbol}` decoded through InstrumentKey validation, venue BYBIT and product SPOT|LINEAR. Account = exact `{account_id,environment}` using ProductScope account validation (identifier length1..256, no surrounding whitespace or control characters; DEMO|LIVE). References = exact `{strategy_id,revision}` validated through the catalog rules.
Retain streamed HTTP64KiB bound, nested duplicate rejection and current V1 lexical/count/list rules. Bound stored schema2 payload to64KiB UTF-8 before parsing; bound canonical output likewise. Catalog individual maxima do not override total size: an otherwise shaped catalog can still be too large. Do not raise body limits to accommodate a maximal Cartesian catalog.

## Policy and section field lists

Policy remains exact `{legacy_v1,scope,strategy,risk_v2}`. legacy_v1 is the unchanged full V1 KEYS object, never a source of typed values. Each new section may be exact null; non-null scope/strategy objects have section_version exact int1 and non-null risk_v2 objects have section_version exact int2, with all listed keys present. Ordinary editable fields may be null as specified; incomplete values remain STOPPED drafts, not valid projections.

Scope exact fields:
- `section_version:1`, `account:Account|null`, `mode:FULL_AUTO|ALL_IN_ONE|null`.
- `allowed_products:[SPOT|LINEAR]|null` (max2, duplicate-free); `selected_product:SPOT|LINEAR|null`.
- `permission_profile_revision:BYBIT_SPOT_LINEAR_NO_FUNDS_V1|null`.
- `allowed_instruments:[Key]|null`, `selected_instruments:[Key]|null`.
Non-null selected_product must belong to a supplied nonempty allowed_products. Every supplied instrument must have selected_product's exact product when selected_product is known; mixed-product universe is invalid. Nonempty selected_instruments requires and is a subset of allowed_instruments. A product change with stale instruments fails; do not filter, convert symbols or select a replacement. FULL_AUTO needs nonempty selected lists for projection; ALL_IN_ONE may persist empty selected lists and projects only an allowed supplied scope. No account/environment/product/mode/universe is copied from legacy_v1.

Strategy exact fields:
- `section_version:1`, `catalog:Catalog|null`, `allowed:[Reference]|null`, `selected:[Reference]|null`.
- Catalog exact `{schema_version:1,revision:CR,entries:[Descriptor]}`; retain complete supplied catalog, not just selected descriptors or only a digest. Recompute its revision with build_strategy_catalog; require equality with the supplied revision.
- Descriptor exact `{reference,implementation_sha256,config_sha256,config_schema_version,engine_contract_version,permitted_instruments,approval_reference,approval_source_reference,approval_source_sha256,approval_environments,approval_status}`.
- Descriptor scalar/list types and bounds are exactly StrategyDescriptor's current contract: H hashes, schema int1..2147483647, ID strings, nonempty duplicate-free instrument list, nonempty duplicate-free DEMO|LIVE environments and APPROVED|DEPRECATED|REVOKED status.
Nonempty allowed requires catalog and exact resolution; nonempty selected requires allowed and exact subset. BEFORE any per-key eligibility derivation, validate the ENTIRE catalog intrinsically and recompute its semantic revision; resolve EVERY global allowed reference exactly, require statically APPROVED status, and require the known account environment in its approval_environments. This includes global references unused by the requested pair/universe; unknown/revoked/deprecated/malformed/environment-mismatched allowed values fail the whole draft/projection rather than being filtered out. If account is null, environment is missing, not invented; intrinsic/status/reference checks still apply. Catalog can preserve non-allowed deprecated/revoked entries. FULL_AUTO needs nonempty selected strategies; every selected ref must be an exact global allowed ref.
Heterogeneous domains are supported through the existing descriptor.permitted_instruments only. Do NOT require every allowed descriptor to permit every allowed instrument, add a wire matrix, or rewrite global sets to make a catalog call pass. A valid globally allowed descriptor can be ineligible for one key and eligible for another; retain its complete metadata and original global order in the draft.
For each exact Key k, AFTER full global validation, derive eligible_allowed(k) by retaining those references from global allowed, in their original order, whose resolved descriptor permits k. Derive eligible_selected(k) by retaining references from global selected, in its original order, that occur in eligible_allowed(k). This is explicit eligibility derivation, not filtering invalid input: no unknown/unapproved/environment-invalid value may reach this step. Null selected lists become an empty tuple only where ALL_IN_ONE treats selection as optional.
Effective universe U is scope.selected_instruments for FULL_AUTO and scope.allowed_instruments for ALL_IN_ONE. Active refs for k are eligible_selected(k) for FULL_AUTO and eligible_allowed(k) for ALL_IN_ONE. For complete projection, supplied scope.instrument must be an exact member of U and scope.strategy an exact member of that key's active refs (plus the global allowlist); ALL_IN_ONE candidate construction may use only eligible_allowed(k), never the raw Cartesian product. No requirement says every valid allowed/selected reference must be used by some key; unused valid refs stay pinned but generate no fabricated pair.
With nonempty eligible_allowed(k), call existing require_strategy_references(catalog, expected_catalog_revision=catalog.revision, allowed=eligible_allowed(k), selected=eligible_selected(k), instrument=k, environment=persisted_account.environment). Both tuples are genuine derived subsets, preserving their respective original orders, not a fabricated singleton containing the requested strategy. Verify the returned descriptors and the supplied mode-specific membership. If eligible_allowed(k) is empty, do not fake one to bypass STRATEGY_ALLOWLIST_EMPTY; coverage/projection refuses it.
Persist full implementation/config/engine/approval-source/permitted-instrument pins without substituting another revision. A caller-provided APPROVED string and matching digest establish metadata consistency only. No artifact bytes, approval source authenticity, current approval, revocation freshness or issuer authority is established.

Risk exact fields:
- `section_version:2`, `product:LINEAR` (non-null discriminator), `sizing_rule:LOSS_FIXED|null`, `caps:Caps|null`.
- `leverage_min`, `leverage_max`, `per_trade_loss`, `max_daily_loss`, `max_drawdown`, `max_total_risk`, `max_total_margin`, `margin_allocation`: each positive D|null.
- `max_stop_gap_quote_per_base`: positive D|null, in USDT per one base unit. This is the operator-declared additional adverse-execution budget from stop trigger onward, not a price or exchange-guaranteed execution bound. An old risk_v2 section with the exact v1 field set is read-normalized to section_version=2 and None; never supply a guessed numeric default. None is reported as missing and blocks cost allowance issuance and loss-plan sizing until the operator explicitly sets and saves a value.
- `max_consecutive_losses`, `max_positions`: each I|null.
- `margin_mode:ISOLATED|CROSS|null`, `position_mode:ONE_WAY|null`.
- `liquidation_buffer_fraction`, `max_quote_age_seconds`, `max_evidence_age_seconds`: each nonnegative D|null; buffer<1. Compare supplied leverage bounds exactly without float arithmetic.
- Caps exact `{max_order_admission_notional,max_account_admission_notional,valuation_rule,turnover_requirement,max_execution_quote_amount}`; amounts positive D|null, valuation_rule `LINEAR_MARK_GROSS_AT_ADMISSION_V1|null`, turnover_requirement `NOT_REQUIRED|HARD_EXECUTION_QUOTE_CAP|null`.
All Caps fields are required even when null. NOT_REQUIRED requires max_execution_quote_amount=null. HARD with null amount is an incomplete draft; HARD with positive amount is structurally valid. A positive amount with null requirement remains incomplete and never implies HARD. No automatic cap relationship or SELL upper-bound value is invented.
If selected_product is SPOT, risk_v2 must be null. Preserve the SPOT selection; display its full risk/protection policy as unsupported pending E16. Never supply futures zeros/ones or cast it to LINEAR. A LINEAR risk object may exist before scope is complete; projection waits for all required scope fields.
capital_usdt and max_total_notional remain legacy values only. There is no capital field in LinearRiskPolicyV2. A10 must not claim legacy capital constrains the new policy or map one legacy notional into two new caps. A separate program cash-allocation policy, if required, needs an explicit later typed contract.

## Missing fields, projection and revision

missing_fields is sorted and deterministic. A null section contributes its section name (the all-null baseline stays exactly ['risk_v2','scope','strategy']); a present section contributes dotted paths for required null/empty fields. Optional selected lists under ALL_IN_ONE contribute no missing path; NOT_REQUIRED's null execution amount contributes none. SPOT still contributes risk_v2 and an explicit unsupported-product blocker; complete metadata is never execution readiness.
Pair coverage is derived, never persisted as a new wire matrix. Once account/mode/catalog/global allowed refs and the nonempty effective universe U are supplied and globally valid (and FULL_AUTO's selected refs are nonempty), any k in U with no active refs is an orphan. Accept it as a STOPPED partial draft but add the fixed missing path strategy.eligible_pairs once; the UI derives and names the exact affected keys. Until those prerequisites exist, report their ordinary missing paths instead, not a speculative coverage result. A complete-policy risk projection refuses ANY orphan in U with POLICY_V2_ADMISSION_REQUIRED, including a request for another covered key; the operator must explicitly fix the draft. Unselected allowed keys outside FULL_AUTO's U do not create that coverage missing path, but cannot themselves be projected. An unavailable requested pair for an otherwise covered policy fails RISK_V2_SCOPE_MISMATCH; never substitute another key/ref. A valid unused strategy creates no missing path solely because it is unused.
Example: FULL_AUTO selected X/Y and A(X)/B(Y), all globally valid, has full coverage; project(X,A) and project(Y,B) pass static consistency, while project(X,B) and project(Y,A) fail. ALL_IN_ONE for X derives only A and for Y only B. Adding orphan Z to U makes the draft incomplete; adding an unknown/revoked reference to global allowed rejects the draft even if Z or that ref is not requested. Existing admission/native/worker/current-publication blockers remain regardless of coverage; empty missing_fields never grants readiness.
Keep the eight read-response keys. Always retain POLICY_V2_ADMISSION_REQUIRED, NATIVE_RUNTIME_NOT_QUALIFIED and WORKER_NOT_CONNECTED; typed strategy metadata additionally reports STRATEGY_CURRENT_PUBLICATION_REQUIRED. SPOT reports POLICY_SPOT_RISK_UNSUPPORTED. No `approved`, `ready`, `qualified` or `running` derived bool is added.
`RuntimePolicyBook.risk_policy_v2(scope:RiskScopeV2)->LinearRiskPolicyV2`: read and globally validate one persisted snapshot before eligibility derivation; reconstruct exact DTOs afresh through public constructors; require complete LINEAR scope/strategy/risk sections including effective-universe pair coverage; compare supplied account+environment+product+instrument+exact strategy reference against persisted full metadata and the exact per-key mode restrictions above. Return scope equal to the exact supplied scope, never a scope synthesized from the first universe entry. Known wrong key/ref/pair is RISK_V2_SCOPE_MISMATCH; unresolved global input remains a validation failure, not an ineligible pair silently omitted.
Use revision=str(snapshot.revision), the decimal canonical form of the global integer revision, not a new catalog hash or a static V2 label. Return all risk fields and LinearCapitalCapsV2 directly from the typed risk section; Decimal conversion is exact and never reads legacy_v1. Use risk_policy_sha256_v2 on the returned DTO for its existing economic digest; catalog content pins remain separately persisted and must be captured by Task13, since that digest does not cover full strategy metadata.
Require every financial field, cap meaning and applicable turnover amount. If new cap amounts/valuation/turnover choice are absent, raise RISK_V2_CAP_POLICY_MIGRATION_REQUIRED even if legacy max_total_notional is present. Other incomplete scope/strategy/risk fails POLICY_V2_ADMISSION_REQUIRED; scope/ref mismatch fails RISK_V2_SCOPE_MISMATCH; unsupported product fails RISK_V2_UNSUPPORTED_PRODUCT. No supplied account/market/source/model observation is created here.
MARK_GROSS_AT_ADMISSION values measure quantities using current mark at admission and do not promise a lifetime fill-turnover bound. HARD_EXECUTION_QUOTE_CAP separately requires a real execution quote upper bound; saving/projecting HARD does not provide it. A SELL limit floor is not an upper bound: Risk2–6 must continue rejecting hard SELL when actual upper evidence is unavailable. CROSS can be represented by the existing DTO, but actual model qualification/admission remains unsupported until independently implemented; ONE_WAY is the only typed position mode here.
Keep `risk_policy(RiskScope)` V1 behavior and immediate schema2 refusal unchanged; no fallback or positional reconstruction into V1.
